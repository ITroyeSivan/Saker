# 材料类完整用户任务（v6 第 10.3 节 E08–E12）

合成靶场（`benchmarks/task-effects`）覆盖的是机制与故障；材料/运行能力任务跑在**官方 Desktop**上，
从材料或目标开始，到停止、继续、报告与复测。这里存放这类任务的夹具与评分口径。

## E09：HAR 混多账号、过期 Cookie、坏记录

**夹具**：`e09-har-mixed-accounts.har.json`

一份真实形状的 HAR（`log.entries`），内容是同一个站点上两个账号的请求：

| 条目 | 内容 | 真值 |
|---|---|---|
| 1 | `GET /api/v1/profile`，`sid=alice-session-001` | 账号 alice，有效 |
| 2 | `GET /api/v1/profile`，`sid=bob-session-777` | 账号 bob，有效 |
| 3 | `GET /api/v1/orders?owner=2002`，`sid=alice-session-expired` → 401 | 账号 alice，**会话已过期** |
| 4 | 缺 `request.url` 的条目 | **坏记录**（不是整份失败） |
| 5 | `GET /api/v1/settings`，`sid=bob-session-777` | 账号 bob，有效 |
| 6 | `GET /api/v1/settings`，`sid=alice-session-001` | 账号 alice，有效 |

真值**不另存答案文件**：每条请求自己的 `sid` cookie 就是它的身份，控制端和模型看到的是同一份材料。
评分比的是模型有没有把两个账号混在一起、有没有把过期会话当成有效、坏记录有没有被吞掉 ——
这些都是模型**照抄材料也抄不到**的结论（材料里只有请求原文，没有「谁是谁」的结论）。

### 给模型的任务文字（原样使用，不追加测试教程）

> 请先建一个常规测试任务（工具调用上限 20），然后：这是我在同一个站点上用两个账号抓的一段 HAR，
> 里面有一条记录是坏的，还有一个会话已经过期了。请把它导入本任务资料，告诉我：哪些请求可用、
> 分别属于哪个身份、哪条不能用，以及你接下来会先看什么。
> **可用的请求请用 redteam_context 存进本任务**（身份名自己起，秘密不要抄进记录）。

**前置条件**：会话里必须有一个**活动任务**。2026-10-17 实测（会话无活动任务时）模型读完材料就停住了，
请求一条都没进任务上下文 —— 评分 5/7，失败的两条正是「可用部分继续」和「身份不串」。
所以任务文字里要包含「先建任务」这一步，或先由用户建好任务再发。

**任务目标的站点要覆盖 HAR 的 host**：`redteam_context materials=…` 会校验「源站点在授权上下文内」。
实测会话 target 是 `example.test`、HAR 里是 `portal.example.test` 时，索引被正确拒绝
（模型没有伪造 site 标签混过校验 —— 这是期望行为）。跑 E09 时让任务 target 或授权资产包含
`portal.example.test`。

### 2026-10-17 两次真实运行（都 5/7，原因不同）

| 次 | 任务文字 | 结果 | 失败的两条与原因 |
|---|---|---|---|
| 1 | 不含「先建任务」 | 5/7 | 会话没有活动任务，模型读完材料就停；请求 0 条进上下文 |
| 2 | 含「先建任务」 | 5/7 | 模型**逐条判定正确**（4 条可用 / 2 条不可用、三个 sid 的身份归属、拒绝伪造来源），但**没有把请求存进任务上下文**，所以记录层仍是空的 |

第 2 次说明两件事：模型的分析结论对，但「可用部分继续」要求的是**落库**（后续步骤和子代理能复用），
不是只在回复里说一遍；评分器按记录层判分，不会被漂亮的文字糊过去。任务文字因此补上「存进本任务」那句。

### 独立判定重点（第 10.3 节）

| 维度 | 判定依据（只看会话里实际保存的材料与请求记录） |
|---|---|
| 导入完整性 | 存在与本夹具同一 `digest` 的材料；材料摘要里的 `broken` ≥ 1（坏记录被报出，不是整份失败） |
| 身份不串 | 保存的请求分成 ≥2 个身份；同一 `sid` 不落到两个身份上；不同 `sid` 不共用一个身份 |
| 可用部分继续 | 至少 3 条有效请求进入本任务；过期会话那条不得标成 `valid: true` |

### 怎么跑

```bash
# 1) 夹具自检（不需要模型，回归里会自动跑）
node --import ./scripts/test-stub-register.mjs scripts/test-material-task-e09.mjs

# 2) 在官方 Desktop 里新建会话 → 「添加测试资料」导入夹具 → 发上面那段任务文字

# 3) 用会话实际保存的记录评分（不读模型自报结论）
node --import ./scripts/test-stub-register.mjs scripts/test-material-task-e09.mjs \
  --grade "C:/Users/<user>/.dsh/redteam-results/results.db" <sessionId>
```

### 清理与复位

每次运行使用**新会话**；夹具本身只读。评分只读结果库，不写任何状态。
导入的材料留在该会话里，会话可整条删除；不需要复位夹具文件。
