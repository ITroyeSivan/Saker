# dsh-ctf-observer

CTF 模式的 **Observer sidecar** —— 照搬 BreachWeave 三角色里「旁路监督」那一环。

## 它做什么

在**轮次边界**（`turn/end`）对最近的工具流做**确定性检查**，命中就注入**一条**纠偏提醒：

| 判据 | 触发 | 提醒什么 |
|---|---|---|
| 重复试错 | 同一 `工具+参数` 指纹出现 ≥4 次 | 换一条独立思路，或把这条登记为已证伪 |
| 错误堆积 | 连续 ≥3 个工具报错 | 先解决当下这个错误，别叠加新尝试 |
| 无进展 | 连续 ≥4 轮没有出现**新的指纹** | 大概率在原地打转，换路或先做会做的题 |
| 周期体检 | 每 6 轮 | 保持节奏；确认哪条方向最接近 flag |
| **flag 已捕获** | 工具输出里出现 flag 形态 | **系统判定可收尾**（结束条件外置） |

> 「无进展」判的是**指纹**（工具+参数），不是「工具种类」。工具种类是有限集合（十几种），
> 会话一长必然"全都见过"→ 永远判成无进展，那是**必然发生的误报**。

## 协作看板（Manager 面）

单会话里由模型自己当调度者 —— BreachWeave 的 Planner·Manager + 共享协作状态落地为
工作目录下的 `ctf-board.json`，配套四个模型工具（只在 `ctf-solver` 模式可用）：

| 工具 | 作用 |
|---|---|
| `ctf_state` | 读快照：题目 / 已解 flag / 进行中路线 / 未读纠偏 / 最近 observer 记录 |
| `ctf_challenge` | 登记或更新题目（按题名去重；解出后把 flag **原文逐字**填入）|
| `ctf_dispatch` | 派一条攻击路线（多路并行时防撞车的唯一依据）|
| `ctf_steer` | 下纠偏指令 → 入队，由本插件在**下个轮次边界**投递给解题循环并标记已读 |

Observer 每次真正注入提醒时，同源写一条 **Observer Notes** 到看板；steer 队列由 Observer
在轮次边界消费（`consumed: true`）。看板整文件读改写，**所有写路径都走锁**
（`wx` 锁 + mtime 过期回收 + 原子写），多路并行不会互相覆盖。

> 锁的可证伪性单独验证（`_ref/tools/revcheck-board-lock.mjs`）：把无锁实现的临界区加宽后
> 8 并发必然丢 7 条，加锁版同负载 0 丢。单测里那条「并发 8 写全部落盘」**只是冒烟** ——
> 实测本机无锁实现也能过它。

## 它不做什么

- **不替你解题、不验证漏洞**（BreachWeave 原文：observer 不直接代替 solver 解题）。
- **不拦截、不改写**任何工具调用 —— 只注入。
- **不在其它模式生效**（只在 `ctf-solver`）。

## 两道护栏（照 BreachWeave）

- **冷却窗** `REMINDER_COOLDOWN_ROUNDS = 6`：两次提醒至少隔 6 轮。
- **同指纹重复窗** `REMINDER_REPEAT_WINDOW_ROUNDS = 12`：同一个问题 12 轮内不重复念。

两档**叠加**：冷却管"多久内别烦我"，重复窗管"同一个问题别反复念"。
判据是纯函数（`judge`），因此可测 —— 见 `test/run.mjs`（47 条）。**Observer 一旦变成噪音源，比不做还糟**，所以"正常推进中零打扰"是一条硬断言。
