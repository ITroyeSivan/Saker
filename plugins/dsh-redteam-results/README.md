# dsh-redteam-results

自由测试、比赛模式和案例测试的任务、证据、发现与交付插件。

## 工作起点

- **自由测试**：从目标、账号、请求、JS、源码、扫描结果或 CVE 直接开始；常规、Nday、0Day 是方向偏好。
- **比赛模式**：保存题目、附件、交互进程、输出偏移、候选答案和可选本地资料；模型不能自行判定答案通过。
- **案例测试**：读取 Word、Excel 和文本，保存来源位置与修订；结构明确的表格行自动形成检查项，不规则内容保留原文供分析。

公共知识库、固定方法模块和常规转 Nday 流程不参与新任务。研究记录、工作方向和模块选择只作为历史数据保留。

起始范围支持完整 URL、多 URL、域名、通配子域、IPv4/CIDR 和资产清单。用户范围与模型生成记录分开保存；模型写 `inScope:true` 不能扩大授权。聊天中的扩范围、预算或权限变更会形成待用户确认的一条差异。

## 状态与证据

- 任务状态保存范围、身份、预算、协作方式、暂停、阻碍和原用量。
- 完整阴性结论需要本次真实动作或明确复用的观察；问题结论需要关联可复核发现。
- 请求、浏览器页面、截图、下载、文档片段和发现引用分别保存。
- 程序从真实会话事件保存工具调用、输出和模型可见答复；普通答复不要求 JSON、登记 ID 或第二份机器报表。
- 未知写入必须先核对；连接中断后不会自动重放相同业务提交。
- 崩溃恢复只接管确认已停止的运行，活进程不会被第二个窗口抢占。

## 比赛模式

`competition_challenge` 管理题目和附件，`competition_execution` 管理 Host/Docker 交互进程，`competition_answer` 只保存候选值。答案原文不裁剪；通过状态必须带用户或平台确认来源。

`competition_knowledge` 只在该题本地资料开关开启时可用。搜索按来源和正文位置稳定分页，跨过 200 份资料仍可继续，正文按修订和 cursor 分段读取；关闭后工具从下一轮请求中隐藏。

## 案例测试

项目运行使用 `project_document` 读取来源；表格表头与后续数据行在开始前由程序形成检查项。模型直接使用实际执行、请求、浏览器和文件能力，不再需要调用 `project_check`、`project_evidence` 或 finding 登记工具维护账本。

`read`、`write`、`edit`、`pwsh` 等 native 工具调用会按当前有序检查自动建立 action；工具返回保存为 `host-native-tool-result` 证据，正常可见答复到达后检查进入 `needs_check`，程序保留原文和实际依据，不猜业务通过。无进展时只接续一次，之后暂停等待用户明确继续。

检查表显示：

- 原文要求；
- 当前结果；
- 实际做了什么；
- 缺少什么条件；
- 对应请求、页面观察或附件引用。

文件、来源、命令和浏览器/请求观察都可作为实际依据。执行记录保存真实调用、结果归属、时间、身份和实例；旧历史记录继续可读，查看或导出历史不会重放动作。

## 浏览器与请求

目标页面优先使用受管 Chrome for Testing / CDP。直接 HTTP 走可计量执行入口，保存方法、目标、身份、状态、响应摘要和完整回执。范围、排除路径、只读和并发限制在派发前检查。

普通探索可用 `redteam_execution action=direct` 直接提交范围内的 URL、方法、身份和请求体；也可对已存请求用 `action=run`。适配器自动保存入口资产、请求和响应。方法、基线和研究方向只用于需要复现或对照的验证，不再拦截所有普通请求。

## 交付

结果页分别提供执行记录、发现的问题和测试资料。导出包含检查表、发现、复现材料、请求回执、截图和附件；导出本身不访问目标，也不调用模型。秘密字段按常见请求头和 JSON 字段脱敏。

## 归档兼容

- 新归档：`saker.task-archive/4`，包含自动保存的工具结果和模型可见答复。
- 兼容旧归档：`saker.task-archive/3` 与 `/2` 完整校验后恢复；`/2` 中退役知识区安全忽略。
- 项目来源、材料、身份引用、发现、证据和自动事实继续恢复。
