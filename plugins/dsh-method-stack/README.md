# dsh-method-stack

**提示词模块化方法栈**——把「怎么测」从一段写死的提示词，拆成可勾选、可覆盖、可追溯的方法积木。

## 它解决什么

渗透测试的提示词插件大多是一整块文本：流程顺序、判断标准、输出要求全写死在里面。你想改一个环节，只能整段替换；团队里不同人的方法论不同，也没法共存。

本插件把测试逻辑组织成 **模块组（group）→ 子方法（method）** 两级：

- 每个方法是一个独立目录，`manifest.yml` 写元信息（名称、描述、排序），`prompt.md` 写正文。
- 设置页「方法编排」勾选启用哪些方法、按什么顺序注入。
- 用户层同名目录直接覆盖官方正文，不用改包。

注入方式是注册固定的 `systemPrompt.context`（`order 460`，位于 `dsh-route-boost` 的 500 之前），按 agent → preset 读取该模式的方法组合，把启用方法的正文按 order 拼装进每一轮。用户改动组合后**下一轮即生效**，无需重启。

## 自定义

**用户层覆盖**（推荐，不改包）：

```
~/.dsh/method-stack/methods/<group>/<id>/
├── manifest.yml
└── prompt.md
```

同名目录会替换官方的描述与正文（用户优先）。为避免孤儿条目，用户层只接受官方也存在的 `id`。

**设置页操作**：勾选组合、克隆官方方法到用户层编辑、保存自定义组合、恢复默认、预览渲染结果、编辑开头语（opening）。

**组合持久化**：`~/.dsh/method-stack/profiles/<presetId>.yml`。组合内容变化递增 `rev`，并追加 `~/.dsh/method-stack/audit.log`（时间 / 模式 / 组合 / rev），改动可追溯。

## 会话内使用

输入框上方有一个「方法 ▾」按钮，显示当前模式已启用的方法数（如 `渗透测试 12`）。点开可以直接勾选/取消单个方法、按组「仅此组」切换、把当前勾选另存为组合、一键套用已存组合。**变更在下一轮模型请求生效**，不需要重启或新建会话。

完整的目录浏览、正文编辑、克隆与恢复默认，在「设置 → 方法编排」。

## 配置

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enable` | boolean | `true` | 关闭后不注册上下文节 |

## 边界

- 单个方法正文超过 6000 字符会被截断（上下文成本保护）。
- 方法只影响提示词层，不改变工具行为；纪律类硬约束由 `dsh-sec-enforce` / `dsh-stage-gate` 负责。
- 与 `dsh-attack-atlas` 的分工：本插件管「方法正文怎么写、这一轮用哪些」，AttackAtlas 管「方法之间怎么接线、覆盖到哪一格」。
