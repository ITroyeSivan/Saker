# Saker 0.7.14

本版补齐组件 Nday 的第一段结构化链路：组件事实、公告前提、适用性和真实执行证据分开记录。

### ✨ 新增功能

- `saker_component` 支持 `observe`、`advisory`、`evaluate` 和 `status`。
- 组件事实绑定产品、版本、目标资产、材料/回执来源和观测时间。
- 公告支持规范化对象和 OSV 受影响范围；记录引入版本、修复版本和必要前提。
- 同一记录支持 `kind=security-change`，保留上游 URL、commit、修复版本、变更文件和变更摘要；目标可达性仍作为独立前提。
- 适用性结果为 `applicable`、`not-applicable` 或 `unknown`，并列出每个必要前提是否满足。
- 前置条件接受对象、数组和嵌套 document 输入；`state`、`evidenceRef` 按候选实际返回记录。
- `nday-default` 与 `code-default` 方法在识别、公告和安全变化步骤中调用该工具。

### 🐛 问题修复

- 产品/版本命中不再被当成漏洞；仍要求目标入口真实执行、正常对照和影响验证。
- 缺版本、范围不可比较或前提未知时明确返回 unknown，不猜受影响。
- 公告来源必须指向当前会话的材料、项目来源或执行回执。

### 🎨 体验优化

- 组件事实和评估保存在当前会话，结果可回读；不新增第二个任务中心。
- CTF 和标准模式不显示该工具，避免把解题会话当成组件审查。

### ⚠️ 其他变更

- 可信开源仓库自动追踪、漏洞版/修复版构建和逐目标可达性仍是后续边界。
- 不发布、不 push、不提交 Git。
