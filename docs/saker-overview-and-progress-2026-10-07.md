## 1. Saker 做什么

Saker 是官方 DeepSeek Harness Desktop 的安全测试插件集。它把测试模式、工具配置、MCP、公开漏洞资料、任务记录和成果整理放在同一个桌面应用中。

现在只有一个新任务入口：**Saker 渗透测试**。下面有三个子模式：

| 子模式 | 适合什么时候用 | 主要工作 |
|---|---|---|
| 常规测试 | 只有机构名称或站点，尚不清楚从哪里开始；或已有具体功能要检查 | 整理入口、理解功能，检查接口、权限和业务流程 |
| Nday 发现 | 已经知道系统采用什么产品，或已有版本、组件、扫描线索 | 查相关公开漏洞，核对适用条件，验证少量有依据的候选 |
| 0Day 挖掘 | 已经有业务异常、可疑请求或值得追查的功能 | 沿页面、JS、请求和身份关系深入研究，确认原因和实际影响 |

代码审计和 CTF 已退出新任务模式，历史记录仍可查看。相关资料和分析能力可以辅助当前测试，不需要另开一种模式。

三个子模式共用已经取得的资产、请求、材料和证据。切换研究重点不应重新收集一遍信息，也不应给同一个站反复创建新代理。

这里的“0Day 挖掘”表示研究方向。没有公开漏洞编号，不足以证明发现了真正的 0Day。

## 2. 只有机构名称，怎么开始

可以直接给机构名称。**不需要先手工整理完整资产清单、收集全部 JS，或给每个系统准备一套信息。**

目前建议这样操作：

1. 双击桌面的 **Saker (dsh Desktop)** 快捷方式。
2. 新建会话，选择 **Saker 渗透测试 → 常规测试**。
3. 在输入框上方设置协作方式和子代理人数，在「设置」中独立选择汇报量；点击「写提示词」，选择机构入口示例并填写名称，也可自由编辑后插入或复制。如果已有范围说明或规则链接，一并提供。
4. Saker 先整理公开入口和归属依据，给出最多三个值得继续检查的系统。范围已经明确的，可以按约定继续；范围不明确的，集中确认一次。
5. 有可靠产品线索时继续做 Nday 检查；有具体业务疑点时再深入研究。需要账号或正常请求时，说明具体缺什么，不要求你预先准备整个机构的所有材料。

```text
机构：［机构名称］。
已有测试范围或规则：［有则填写，没有则注明暂未确认］。

我没有整理资产清单。请先从公开资料确认官网、业务系统入口和资产归属，最多列出三个值得继续检查的系统，并说明理由。

范围明确后，先选一个系统推进常规测试；发现可靠产品线索时，复用已有资料做相关 Nday 检查。归属或可测范围不清楚的，集中向我确认一次。

主代理先做，确有需要才分一个站点子代理，同站复用，结束后释放。相关线索连续检查，不逐个疑点打断。需要登录或关键资料、正常访问失败、IP 被封时停下说明原因。
```

机构名称可以作为入口整理的起点，但不能证明搜索结果中的所有系统都可以测试。EDUSRC 收录或接收报告，也不能单独代替具体目标的测试范围。

如果缺少搜索服务、资产查询服务或所需工具，Saker 应明确说明能力缺口，不能把推测写成已经收集到的结果。

点击聊天栏「设置」可以选 **“收集后自动接 Nday”** 或 **“常规与 Nday 同时进行”**。子代理上限为0–16整数，默认1，按需使用并同站复用。协作方式默认「自主推进」，需要参与决策时可选「共同研判」或「关键节点确认」。汇报量独立选择，不改变确认节点；已有等待仍需明确继续，可直接补充业务思路。

## 4. 本轮完成的改动

### 4.1 每个模式提供可复制示例

不用每次重新组织一段长提示词。

- 点击子模式后显示该模式的示例。
- 常规测试、Nday、0Day 各提供三个不同用途的示例。
- 示例可以展开阅读，也可以直接复制；复制本身不会开始任务。
- 复制失败要给出明确提示，并允许手工选择文本。
- 同一处可选择测试安排和子代理上限。

九个示例已在真实桌面中复制核对，粘贴换行归一化后内容一致；复制不启动任务。临时模拟剪贴板失败时出现手工复制提示。

### 4.2 常规与 Nday 在同一任务中衔接

提供三种安排：

| 安排 | 应有行为 |
|---|---|
| 只做当前模式 | 完成这一轮约定的工作后结束 |
| 收集后自动接 Nday | 保存入口和产品资料、释放当前子代理后，自动接着检查相关公开漏洞，不需要再发一句“继续” |
| 常规与 Nday 同时进行 | 检查具体业务的同时处理相关产品线索，两部分各自记录进度，全部完成才结束 |

“同时进行”不表示一定创建两个代理。没有子代理时由主代理交替推进；确有必要分工时，才把清楚的一项工作交给站点子代理。

两部分必须共用原来的范围、已用操作数、截止时间和子代理上限。不能切换一次模式就重新获得一份预算。

流程状态、完成标记和宿主续接已通过真实桌面合成资料验收。自动续接按已选交互频率执行；阶段确认等待用户点击继续，取消、受阻或预算耗尽时停止。

### 4.3 控制子代理数量和回收

子代理上限提供 **0、1、2** 三个选项，服务端也检查这个上限，不能只靠提示词提醒模型。

- 常规和 Nday 共用一个上限，不能各派一组。
- 同一个站保留并复用原子任务，续接时保留资料和历史。
- 子代理不能继续分发子代理。
- 正在启动、运行、关闭，以及关闭失败的子代理都占名额。
- 结束、取消、失败或等待资料时保存报告并回收。
- 关闭失败要显示出来，不能把它当作已释放再派一个。

同站跨阶段续接的回归和真实桌面验证已完成：原 childId 冷恢复，保留预算、截止时间与历史报告，Nday 本地策略工具实际可调用，结束后释放。首次分派前必须加载 Nday 工具包，服务端会拒绝不完整的工具清单。

### 4.4 修复发布包中的截图遗漏

桌面打包脚本已复制截图目录，发布包包含 README 引用的实际图片；ZIP 按清单核对内容。

## 6. 交互频率怎么选

- 没时间频繁回复：选 **仅必要时询问**。在原范围与预算内连续推进，结束时集中汇总。
- 希望看阶段进展但不用回复：选 **阶段汇报，自动继续**。
- 希望阶段之间自己决定：选 **阶段完成后等我确认**。聊天中直接提供“确认并继续”和停止按钮。

三种选择都在聊天输入框上方；「更多设置」可把交互频率和人数保存为新会话默认。完成一轮后，聊天中可保留资料并设置下一轮。

任务中改频率不会重置预算。已经等待的阶段仍需一次显式确认，不能把等待当成任务结束来开新预算。等待期间原截止时间继续计时；缺关键资料、需要登录、范围不明或访问受阻时，任何频率都应停下说明。

本轮验证使用虚构产品、占位地址和离线状态夹具。最初在原工作区的模型回合曾额外读取历史材料，之后改用独立合成工作区，历史内容不进入发布证据。完整结果见 [0.4.88 发布检查](verification/release-0.4.88.md)，发布与下载见 [v0.4.88](https://github.com/ITroyeSivan/Saker/releases/tag/v0.4.88)。

## 7. 实战效果应该怎么看

目前能证明的是流程、材料复用和部分受控场景有所改善，**还不能证明真实目标的漏洞检出率提高，也不能保证每次都省 token**。

此前五组桌面模型对照中，常规、0Day 和子代理场景的 token 用量有所减少，但 Nday 那一组增加了 **23.56%**。每组只测一次，不能据此推导所有任务的效果。

本轮的目标是减少手工写提示词、重复收集和无效分发。实战是否更高效，后续需要在相同模型、范围和预算下比较：获得了什么有效信息、是否形成可复核结果、花了多少 token 和时间，以及为什么停下来。疑点数量和扫描输出数量不能替代这些指标。

## 8. 关于当前对话被中断

用户提供的提示是“无法显示此内容”，并明确提到网络安全内容和 Daybreak。可以确认这是平台内容安全拦截，但没有详细审核理由，无法定位到具体触发句子，也不能据此认定用户违规。

这与某次桌面操作是否要求登录、某个 MCP 是否在线，需要分别核查。本轮验证使用本地测试资料，不尝试绕过平台限制。平台提示中的授权安全工作入口：[申请 Daybreak](https://chatgpt.com/cyber/)。
