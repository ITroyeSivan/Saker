# Saker的框架

Saker是官方dsh Desktop上的模式包与功能插件。模式包规定如何围绕人的问题工作；插件提供资料、工具、任务与证据记录。插件之间存在实际数据和接口关系，不能随意移除依赖后认为所有流程仍能运行。

## 一轮任务如何推进

1. 人提供站点和资料，与主代理确定一个小问题。
2. 主代理建立本轮范围、身份和预算，已有事实直接复用。
3. 主代理研究相关材料；确有必要才分给一个站点子代理。
4. 按本轮判断执行有限对照，程序保存回执和差异。
5. 根据结果继续相关路径；遇到真正阻碍停止并说明。
6. 保存发现和未覆盖内容，释放本轮创建的子代理，再与人选下一轮。

常规、Nday和0Day是同一渗透会话的三种重点，不是三个扫描器，也不需要三套代理。人的补充交给原任务和原子代理。

## 各部分负责什么

| 部分 | 主要位置 | 职责 |
|---|---|---|
| 模式与工作说明 | preset/pentest、lib/preset-visibility.mjs | 一个专业入口、三个子模式，保留旧会话 |
| 任务与站点协作 | dsh-redteam-results/task-policy、site-workers | 范围、共享预算、停止与续接、必要性判断、数量和真实释放 |
| 业务资料与事实 | business-materials、task-context | 已有资产、角色、对象、报文、文件摘要和相关片段 |
| 公开漏洞与方法 | dsh-nday-hunter、dsh-method-stack | 条件相关的情报检索、来源维护、按需读取方法 |
| 工具声明 | dsh-tool-scope | 当前代理实际工具清单，按需加载资产、Nday和扫描包 |
| 执行与效果 | comparison-jobs、execution-receipts、effect-verifications、impact-reviews | 对照回执、重复缓存、自动效果检查和明确标识的人工复核 |
| 成果与桌面操作 | dsh-redteam-results/client、delivery | 本轮状态、证据详情、停止恢复和可交付成果 |

材料摘要、模型解释、实际请求回执和影响证明分别保存。声明执行过不等于产生影响；影响复核随请求、方法和范围变化失效。共享知识不能替代另一站的身份和目标证据。

## 子代理的生命周期

默认没有子代理。分派前核对实际存活列表和已有记录，同站不另建，下级分派被禁止。结束先保存短报告，再等待宿主终态并释放；报告已提交与释放完成之间的短暂中间态必须区分。关闭失败仍占名额。恢复使用记录续接，不依赖永久保留活代理。

## 验证与安装

源码、打包和安装有独立校验。回归检查覆盖数据和约束，最终还须在官方Desktop操作改动后的流程，检查插件激活和可见错误。成本通过真实模型请求元数据及会话用量核对，合计所有参与代理；不能用源码估算或模拟推断实战效果。
