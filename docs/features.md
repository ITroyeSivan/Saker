# Saker能帮你做什么

Saker运行在官方dsh Desktop。新建专业会话只选“渗透测试”，下面有常规测试、Nday发现、0Day挖掘三个子模式。旧代码审计和CTF会话保留历史，阅读源码仍可作为渗透任务的一部分。

## 先选一个具体问题

你提供一个站、已有账号或报文、业务用途以及本轮想查的问题。比如“这个普通账号能否查看别人的人员档案”。已有信息够用就直接推进；只有URL时先有限观察，再与你选方向。不会收到一个域名就展开整个机构。

相关疑点连续查，无关线索先记下。发现每个疑点不都暂停；缺关键资料、有效路径走不通、需要改变范围或花费、当前任务结束时再讨论。IP封禁、正常访问失效、登录过期和实际工具限制及时停止受影响请求，说明依据和未覆盖内容。

## 三个子模式

| 子模式 | 工作重点 |
|---|---|
| 常规测试 | 理解选定功能的正常行为，比较角色、对象、参数和业务步骤 |
| Nday发现 | 根据已有产品证据查少量相关公开漏洞，核对条件后验证 |
| 0Day挖掘 | 沿业务疑点追页面、JS、请求和必要源码，比较实际处理结果 |

三个子模式共享站点、身份、请求和研究记录。Nday来源更新属于维护，不要求每次测试重新更新全部源。没有公开编号也不自动认定为首次发现。

## 材料分析与实际验证

从JS中定位真实调用、凭证用途、角色字段、对象参数、上传和导出等业务联系。只取相关片段，未变化的材料复用，动态调用和缺失文件明确留作未覆盖。公开客户端Key、菜单显隐和HTTP 200都只是事实，需要结合权限预期和实际效果判断。

已登记的正常与异常请求可以批次比较，保存真实回执和差异。相同工作复用结果；结果未知时不自动重发。模型解释差异后再选择下一步。自动效果检查只用于支持的方法，其他权限或业务效果可在成果页人工复核，并标明这是操作人的判断。普通响应和回连不能被写成执行证明。

## 子代理只在确有需要时使用

短任务由主代理直接完成。需要隔离大量站点材料或承担明确的深入工作时才分派，说明必要性和结束条件。通常一个，最多两个；同站复用，子代理不能继续派代理。

完成、失败、取消、超时或等待人补资料时，先留记录再释放。正在工作、空闲、正在关闭及关闭失败都占名额；历史记录不算活代理。主任务只清理自己创建的对象。

## 桌面上看什么

成果页展示本轮问题、站点、已用预算、子代理状态和已确认成果。详情查看请求、身份、对象、实际影响和复现步骤；待验证线索、未命中和阻断与可交付发现分开。任务可以停止，恢复前先核对正常基线。

输入框的“方法”按需读取具体正文。工具配置和MCP工作台接入已有能力；资产查询、Nday和扫描工具按需要加载，不每轮带完整声明。

## 效率怎样验证

缩小问题、减少重复读取、批次对照和少量必要子代理能减少无用工作。实际收益要用相同模型、推理设置、资料和预算比较，合计主代理及全部子代理的token、缓存、时间、请求、正例、误报和漏检。当前验收结果见[框架验收记录](verification/framework-desktop-2026-10-03.md)，完整验收前不能宣称已证明实战收益。
