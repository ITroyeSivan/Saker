# 桌面端安装与首次配置

当前版本：Saker **0.5.1**。宿主：Windows 官方 DeepSeek Harness Desktop **0.2.1-rc.2**（同时兼容 0.2.0-rc.2）。

[官方 Desktop](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.2) · [源码仓库](https://github.com/ITroyeSivan/Saker)

## 使用发布包安装

在 [最新版本](https://github.com/ITroyeSivan/Saker/releases/latest)下载并解压 `Saker-0.5.1-desktop.zip`。完成官方 Desktop 的初始化与模型配置，完全退出应用，在解压目录运行：

```powershell
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness" --check
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness"
```

安装完成后使用桌面的 **Saker (dsh Desktop)** 快捷方式。保留解压目录中的 `dist/desktop`，不要删除已安装插件引用的包文件。

## 从源码安装

1. 安装并打开官方 Desktop，完成首次初始化，配置一个可用模型。
2. 获取源码并生成当前安装包：

```powershell
git clone https://github.com/ITroyeSivan/Saker.git
cd Saker
pnpm install
node scripts/pack-all.mjs
```

3. 完全退出 Desktop。在源码目录打开 PowerShell，运行：

```powershell
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness" --check
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness"
```

脚本安装需要 Node.js 22.19 及以上的 22.x，或 24 及以上版本；从源码打包还需要 pnpm。它调用指定应用内的官方命令，在一个安装事务中添加 17 个功能插件和根包，并检查已安装文件。当前安装器接受已验证的 Desktop 0.2.0-rc.2 与 0.2.1-rc.2。

安装完成后双击桌面的 **Saker (dsh Desktop)** 快捷方式。脚本每次更新都会刷新它；更换应用目录时保留原来的用户数据目录和 `.dsh` 配置。

请保留解压目录中的 `dist/desktop`：安装后的插件依赖会引用其中按内容保存的 tgz。不要把它当作临时缓存删除。已停用的插件不会被脚本擅自启用，可在官方「插件」页自行开启。

## 安装行为

从旧版升级请优先使用安装器：它先通过官方命令移除已退役插件，再安装当前 18 个包，不删除历史数据库、项目材料或用户配置。

安装器会从 `dist/desktop` 保存按内容寻址的 tgz，再把 profile 依赖指向这些文件。安装完成后不要删除 `dist/desktop`。

如果需要命令行管理插件，通过应用菜单「管理 dsh 命令」安装桌面自带命令；完全退出应用后再操作 desktop profile。不要用 npm 安装的独立 dsh 命令修改它。

```powershell
# 此处的 dsh 必须来自官方桌面菜单
dsh plugin --profile desktop list
```

当前桌面版本使用 `install-desktop.mjs`。`install-all.mjs` 与 `dsh web` 是历史网页流程。

## 首次配置

| 入口 | 需要做什么 |
|---|---|
| 模型 | 选择可用模型；简单验证可用 Low |
| 安全配置 | 填写实际工具路径，检查探测结果；需要时配置 Burp、Yakit 等服务 |
| MCP 工作台 | 导入或添加服务，启动对应进程，检查连接及工具列表 |
| 浏览器 | 在 **安全配置 → 工具 → Chrome for Testing** 选择独立浏览器目录；默认可使用内置或已探测路径 |

MCP 配置存在与服务在线是两件事：Burp/Yakit 没启动时会显示未连接，可用工具为 0。不要因此重新创建一份配置。路径显示不存在的本机工具需补充实际安装位置。

## 开始一个任务

新会话选择「Saker 渗透测试」，先在输入框上方选择 **自由测试** 或 **按文档测试**。其余入口固定为「添加文件 / 写提示词 / 设置」；按文档测试时文件入口显示为「添加测试文档」。常规测试、Nday 发现和 0Day 挖掘在设置中作为方向偏好选择。

在「目标、范围或已有材料」中可以每行填写一个完整 URL、域名、`*.example.com`、IP/CIDR 或资产清单。目标路径和参数会保留，多项输入不会拼成一个主机名。任务开始后仍可在设置中调整用户范围；聊天提出的扩范围、预算或权限变更会先显示为一条待确认差异。

操作、时间、模型调用和 token 上限都是可选的，不再预填 30 次或 15 分钟。需要限制时，在第一次发送前打开「设置 → 开始任务与预算」填写；主代理、所属子代理和后台标题等调用共享模型额度，耗尽后保留结果并停止新生成。切换研究方向不重新领取额度。这里限制的是宿主模型调度次数，不能当作 token 或适配器内部 HTTP 重试次数的硬上限。当前生产路线尚不支持完整严格 token 预算。

点击「写提示词」打开模板库：内置 36 篇，按「开始测试 / 信息收集 / 已知漏洞 / 深入研究 / 分析资料 / 结果与继续」分组，另有「我的」个人模板；搜索支持「越权 / IDOR」「接口 / OpenAPI」「Nday / CVE」等同义词。选一篇后只填 0–2 个关键字段（目标、材料、身份），其余默认值收在「更多信息」里。

「最终文字（发送前可修改）」始终可见：可以直接改写，也可以点「直接编辑」把当前草稿存成纯文本。填好必填项后才能「插入输入框」；没填完时仍可「复制」并在外部改。插入只改聊天输入框内容，不会发送、也不会调用模型。草稿按会话保存，刷新后恢复；同名「另存」创建新副本，不覆盖原模板。

子代理上限按宿主实际支持范围取整（官方 Desktop 默认 0–8，最高 16），界面提供常用人数和「自定义人数」，只显示宿主支持的档位；超出宿主上限会明确拒绝。只有需要时才分派，不使用时由主代理完成。运行中可调整，原操作额度和截止时间保持；正在占用名额的子代理需先关闭，才能降到更低上限。不再提供固定“常规接 Nday”流程；方向切换由用户问题和模型判断决定。

同一处可选择协作方式：

| 选择 | 行为 |
|---|---|
| 自行推进（默认） | AI 在已有范围、资料和预算内自行选择下一步，不要求反复发送“继续” |
| 改动网站数据前问我 | 读取和分析继续；提交、修改或删除业务数据前等待确认 |
| 每个检查步骤前问我 | 先说明这一步要做什么，确认后执行该步骤内的必要调用 |

实战任务可在聊天顶部的「设置」中调整研究方向、协作方式、汇报方式和助手数量；设置先形成草稿，点击保存后生效。研究方向只是重点，不锁死工具或助手对象。已经出现的阶段确认不会因为改选项而自动解除，仍需点一次「确认并继续」；也可选择停止本轮。确认沿用原截止时间，等待期间不会暂停计时或重置操作预算。缺关键资料、需要登录、范围不清、正常访问失败或被封禁时，先处理受影响的检查。会话上方的「执行记录」「发现的问题」「测试资料」分别用于查看调用过程、问题和已有材料；任务状态中的「查看资产」可筛选当前任务引用和本地资产账本，不调用模型。

独立问题可交给助手处理，指定一个或多个已授权资产即可，不要求相同站点或相同研究方向。父子任务共享总预算、取消和写操作归属。IP 被封或正常访问失效时及时停止请求。疑点、已确认问题和交付材料分别记录，响应差异本身不能当作漏洞结论。

普通探索可以直接执行并自动保存实际请求、响应和入口；不要求先建立方法或研究方向。FOFA 原生查询和被动候选整理可只保存候选，不访问候选主机；仍有下一页或配额不足时会保留游标和失败原因。

进度汇报在「设置」中独立选择结束时汇总或每阶段简报。共同研判时可在等待节点补充思路，再按当前思路继续。

## 更新与卸载

更新前完全退出应用，换用新的发布包运行同一安装命令。快捷方式保持原入口与用户数据；重新打开后检查插件版本、MCP 配置和当前任务入口。

每次更新都会在 `%USERPROFILE%\.dsh\backups\desktop-<时间>` 留一份更新前档案：小体积的关键配置
（`package.json`、锁定文件、`cordis.yml`、含 MCP 的 `cordis.patch.yml`），以及更新前的依赖与已启用插件；
安装时加 `--backup-data` 还会整体复制会话与产品数据。

需要退回更新前的状态时，在发布包里执行：

```powershell
node scripts/restore-desktop.mjs            # 列出最近一次备份与回退方案，不写任何文件
node scripts/restore-desktop.mjs --apply    # 完全退出 Desktop 后执行回退
```

回退前会逐字节核对配置副本、并识别数据文件格式，任一不符就停止；执行时先把当前配置另存为
`backups/desktop-pre-restore-<时间>`，所以回退本身也能再回退。回退只还原配置与数据；
装回旧版程序仍需用对应版本的发布包再运行一次安装命令（备份记录里列着当时的依赖与已启用插件）。

卸载可在官方「插件」页进行，或退出后使用桌面自带命令：

```powershell
dsh plugin --profile desktop remove dsh-saker
```

插件卸载不会自动删除历史会话、成果数据库或交付文件。产品使用边界见 [功能说明](features.md)。
