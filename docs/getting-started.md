# 桌面端安装与首次配置

当前版本：Saker **0.4.109**。宿主：Windows 官方 DeepSeek Harness Desktop **0.2.1-rc.2**（同时兼容 0.2.0-rc.2）。

[下载 Saker](https://github.com/ITroyeSivan/Saker/releases/latest) · [下载对应官方桌面](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.2)

## 使用发布包

1. 安装并打开官方 Desktop，完成首次初始化，配置一个可用模型。
2. 下载 `Saker-0.4.109-desktop.zip`，解压到长期保留的目录。
3. 完全退出 Desktop。在解压目录打开 PowerShell，运行：

```powershell
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness" --check
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness"
```

脚本安装需要 Node.js ≥22.5，不需要另外安装 pnpm。它调用指定应用内的官方命令，在一个安装事务中添加 19 个功能插件和根包，并检查已安装文件。当前安装器接受已验证的 Desktop 0.2.0-rc.2 与 0.2.1-rc.2。

安装完成后双击桌面的 **Saker (dsh Desktop)** 快捷方式。脚本每次更新都会刷新它；更换应用目录时保留原来的用户数据目录和 `.dsh` 配置。

请保留解压目录中的 `dist/desktop`：安装后的插件依赖会引用其中按内容保存的 tgz。不要把它当作临时缓存删除。已停用的插件不会被脚本擅自启用，可在官方「插件」页自行开启。

## 在应用内安装

从旧版升级请优先使用安装器：它先通过官方命令移除 AttackAtlas、战役记忆、WebShell 管理，再安装当前 20 个包，不删除历史数据库。手动安装前应在插件页卸载这三项，避免旧入口继续加载。

不想使用脚本时，可在官方「插件」页依次安装发布包内的 tgz：先功能插件，最后 `dsh-saker-0.4.109.tgz`，再按应用提示重启。应用内安装使用桌面自带的 Node 和 pnpm，无需额外安装它们。

如果需要命令行管理插件，通过应用菜单「管理 dsh 命令」安装桌面自带命令；完全退出应用后再操作 desktop profile。不要用 npm 安装的独立 dsh 命令修改它。

```powershell
# 此处的 dsh 必须来自官方桌面菜单
dsh plugin --profile desktop list
```

## 从源码安装

需要 Node.js ≥22.5 和 pnpm。

```powershell
git clone https://github.com/ITroyeSivan/Saker.git
cd Saker
node scripts/pack-all.mjs
# 完全退出官方 Desktop 后：
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness"
```

当前桌面版本使用 `install-desktop.mjs`。`install-all.mjs` 与 `dsh web` 是历史网页流程。

## 首次配置

| 入口 | 需要做什么 |
|---|---|
| 模型 | 选择可用模型；简单验证可用 Low |
| 安全配置 | 填写实际工具路径，检查探测结果；需要时配置 Burp、Yakit 等服务 |
| MCP 工作台 | 导入或添加服务，启动对应进程，检查连接及工具列表 |
| 漏洞情报更新 | 选择来源并更新，查看完成或失败状态 |
| 知识库、技能 | 按本轮问题查阅资料；个人笔记与技能包可导入或编辑 |

MCP 配置存在与服务在线是两件事：Burp/Yakit 没启动时会显示未连接，可用工具为 0。不要因此重新创建一份配置。路径显示不存在的本机工具需补充实际安装位置。

## 开始一个任务

新会话选择「Saker 渗透测试」。聊天输入框上方持续显示任务方向、协作方式、子代理人数，以及「提示词模板 / 添加测试资料 / 设置 / 知识库」四个入口，开始聊天后也保留。先选方向，再提供一个小目标、测试账号和已有材料。

需要限制模型调用次数时，在第一次发送前打开「设置 → 开始任务与预算」，填写本轮问题及可选的模型次数上限，点击开始。主代理、所属子代理和后台标题等调用共享额度，耗尽后保留结果并停止新生成；切换方向不重新领取额度。这里限制的是宿主模型调度次数，不能当作 token 或适配器内部 HTTP 重试次数的硬上限。当前生产路线尚不支持完整严格 token 预算。

点击「提示词模板」打开模板库：内置 36 篇，按「开始测试 / 信息收集 / 已知漏洞 / 深入研究 / 分析资料 / 结果与继续」分组，另有「我的」个人模板；搜索支持「越权 / IDOR」「接口 / OpenAPI」「Nday / CVE」等同义词。选一篇后只填 0–2 个关键字段（目标、材料、身份），其余默认值收在「更多信息」里。

「最终文字（发送前可修改）」始终可见：可以直接改写，也可以点「直接编辑」把当前草稿存成纯文本。填好必填项后才能「插入输入框」；没填完时仍可「复制」并在外部改。插入只改聊天输入框内容，不会发送、也不会调用模型。草稿按会话保存，刷新后恢复；同名「另存」创建新副本，不覆盖原模板。

子代理上限按宿主实际支持范围取整（官方 Desktop 默认 0–8，最高 16），界面提供常用人数和「自定义人数」，只显示宿主支持的档位；超出宿主上限会明确拒绝。只有需要时才分派，不使用时由主代理完成。运行中可调整，原操作额度和截止时间保持；正在占用名额的子代理需先关闭，才能降到更低上限。「设置」中可为常规测试选择只做当前方向、收集后接 Nday、常规与 Nday 一起推进。也可把协作方式、进度汇报和人数设为新会话默认，已有明确设置及运行中的任务保持原配置。

同一处可选择协作方式：

| 选择 | 行为 |
|---|---|
| 自主推进（默认） | AI沿已有范围、资料和预算自行选择下一步，不要求反复发送“继续” |
| 共同研判 | 人提供怀疑点，AI分析证据，当前方向完成后一起判断下一步 |
| 关键节点确认 | AI整理资料并提出路线，切换方向或阶段时等待确认 |

任务开始后直接在聊天里改协作方式，无需切换页面。已经出现的阶段确认不会因为改选项而自动解除，仍需点一次「确认并继续」；也可选择停止本轮。确认沿用原截止时间，等待期间不会暂停计时或重置操作预算。缺关键资料、需要登录、范围不清、正常访问失败或被封禁时，任何协作方式都应停止并说明原因。详细预算、资料、子任务记录和成果在会话上方的「进度与发现」里（概览 / 执行记录 / 发现的问题 / 测试资料）。

小任务通常由主代理完成，确有需要才分派站点子任务。IP 被封或正常访问失效时及时停止请求。疑点、已确认问题和交付材料分别记录，响应差异本身不能当作漏洞结论。

进度汇报在「设置」中独立选择结束时汇总或每阶段简报。共同研判时可在等待节点补充思路，再按当前思路继续。

## 更新与卸载

更新前完全退出应用，换用新的发布包运行同一安装命令。快捷方式保持原入口与用户数据；重新打开后检查插件版本、MCP 配置和当前任务入口。

每次更新都会在 `%USERPROFILE%\.dsh\backups\desktop-<时间>` 留一份更新前档案：小体积的关键配置
（`package.json`、锁定文件、`cordis.yml`、含 MCP 的 `cordis.patch.yml`），以及更新前的依赖与已启用插件；
安装时加 `--backup-data` 还会整体复制会话与产品数据。

需要退回更新前的状态时，在发布包里执行：

```powershell
node scripts/restore-desktop.mjs            # 列出最近一次备份与回退方案，不写任何文件
node scripts/restore-desktop.mjs --apply    # 完全退出 Desktop 后执行回退
```

回退前会逐字节核对配置副本、并识别数据文件格式，任一不符就停止；执行时先把当前配置另存为
`backups/desktop-pre-restore-<时间>`，所以回退本身也能再回退。回退只还原配置与数据；
装回旧版程序仍需用对应版本的发布包再运行一次安装命令（备份记录里列着当时的依赖与已启用插件）。

卸载可在官方「插件」页进行，或退出后使用桌面自带命令：

```powershell
dsh plugin --profile desktop remove dsh-saker
```

插件卸载不会自动删除历史会话、成果数据库或交付文件。产品使用边界见 [功能说明](features.md)。
