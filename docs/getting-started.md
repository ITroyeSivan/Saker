# 桌面端安装与首次配置

当前版本：Saker **0.9.41**。本轮实际可见验收宿主：Windows 官方 DeepSeek Harness Desktop **0.2.2-rc.1**。安装器同时接受 0.2.2-rc.2、0.2.1-rc.5、0.2.1-rc.2 与 0.2.0-rc.2，但这不等于本轮实机验收范围。

[官方 Desktop](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.1) · [源码仓库](https://github.com/ITroyeSivan/Saker)

## 使用发布包安装

从 [Releases](https://github.com/ITroyeSivan/Saker/releases/latest) 下载并解压 `Saker-0.9.41-desktop.zip`。完成官方 Desktop 的初始化与模型配置，完全退出应用，在解压目录运行：

```powershell
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness" --check
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness"
```

安装完成后使用桌面的 **Saker (dsh Desktop)** 快捷方式。

安装器会把 11 个包（10 个功能插件 + 1 个根包）复制到
`%USERPROFILE%\.dsh\saker-desktop-artifacts\desktop`，再把 profile 依赖和锁文件指向这份持久副本。
解压目录只作为本次安装输入，清理解压目录不会让已安装引用失效；再次安装或回退时使用对应发布包。

发布 ZIP 内含 `build-info.json` 与 `packages.json`；`LATEST.json` 和 ZIP 的 `.sha256` 是 ZIP 外部的
附件。学习或复核版本时以三者指向的同一 `buildId` 为准。

## 从源码安装

1. 安装并打开官方 Desktop，完成首次初始化，配置一个可用模型。
2. 获取源码并生成当前安装包：

```powershell
git clone https://github.com/ITroyeSivan/Saker.git
cd Saker
pnpm install
node scripts/pack-all.mjs
```

3. 完全退出 Desktop。在源码目录打开 PowerShell，运行：

```powershell
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness" --check
node scripts/install-desktop.mjs --desktop-dir "C:/实际安装目录/DeepSeek Harness"
```

脚本安装需要 Node.js 24.9 及以上版本；从源码打包还需要 pnpm。它调用指定应用内的官方命令，在一个安装事务中添加 **10 个功能插件和 1 个根包**，并检查已安装文件。

安装器接受 Desktop 0.2.0-rc.2、0.2.1-rc.2、0.2.1-rc.5、0.2.2-rc.1 与 0.2.2-rc.2；
本轮实际可见验收的宿主是 **0.2.2-rc.1**。其它版本的“安装器接受”不等于本轮实机验收范围。

安装完成后双击桌面的 **Saker (dsh Desktop)** 快捷方式。脚本每次更新都会刷新它；更换应用目录时保留原来的用户数据目录和 `.dsh` 配置。

再次安装、隔离验证或回退时使用对应发布包；已安装依赖已复制到上述持久目录，不会随解压目录一起消失。已停用的插件不会被脚本擅自启用，可在官方「插件」页自行开启。

## 安装行为

从旧版升级请优先使用安装器：它先通过官方命令移除已退役插件，再安装当前 11 个包，不删除历史数据库、项目材料或用户配置。

安装器会把 11 个 tgz 按内容寻址保存到持久目录，再把 profile 依赖指向这些文件；新安装的持久目录固定在
`<DSH_HOME>\saker-desktop-artifacts\<profile>`，隔离 profile 的包也留在各自的 home 内。安装完成后可清理
解压目录，但请保留这份持久目录。

如果需要命令行管理插件，通过应用菜单「管理 dsh 命令」安装桌面自带命令；完全退出应用后再操作 desktop profile。不要用 npm 安装的独立 dsh 命令修改它。

```powershell
# 此处的 dsh 必须来自官方桌面菜单
dsh plugin --profile desktop list
```

当前桌面版本使用 `install-desktop.mjs`。`install-all.mjs` 与 `dsh web` 是历史网页流程。

## 首次配置

| 入口 | 需要做什么 |
|---|---|
| 模型 | 选择可用模型；简单验证可用 Low |
| 安全配置 | 填写实际工具路径，检查探测结果；需要时配置 Burp、Yakit 等服务 |
| MCP 工作台 | 导入或添加服务，启动对应进程，检查连接及工具列表 |
| 浏览器 | 在 **安全配置 → 工具 → Chrome for Testing** 选择独立浏览器目录；默认可使用内置或已探测路径 |

MCP 配置存在与服务在线是两件事：Burp/Yakit 没启动时会显示未连接，可用工具为 0。不要因此重新创建一份配置。路径显示不存在的本机工具需补充实际安装位置。

## 开始一个任务

新会话选择「Saker」后，直接在输入框描述目标即可。输入框上方只保留一条操作栏：**方法与状态 / 提示词 / 附件（比赛为题目）/ 更多**。协作和任务设置从“更多”进入，不再各占一行。

在「目标、范围或已有材料」中可以每行填写一个完整 URL、域名、`*.example.com`、IP/CIDR 或资产清单。目标路径和参数会保留，多项输入不会拼成一个主机名。任务开始后仍可在设置中调整用户范围；聊天提出的扩范围、预算或权限变更会先显示为一条待确认差异。

非项目任务在没有桌面覆盖值时的回退上限是 15 分钟、60 次工具调用和 48 次模型调用，最多 2 个活动子实例；
项目任务和桌面已保存的覆盖值优先，因此不能据此声称“每个新会话都是 48 次”。这些是防失控的初始上限，不要求用户填写。
需要调整时，在第一次发送前打开「更多 → 设置 → 节奏」，或明确留空取消插件附加限制。主代理、所属子代理和后台标题等调用共享模型额度，耗尽后保留结果并停止新生成。切换研究方向不重新领取额度。主机提供可靠输入计数与模型准入能力时，token 与模型调用上限在发送前执行；缺少对应能力时整次保存会明确拒绝，不会只保存一个没有守卫的数字。

时间从本轮第一次受管执行或模型准入开始计算。清空四类额度表示取消插件附加限制；运行中把工具或模型上限降到“已用+处理中”以下、或把时间缩到已经过期，整次保存会被拒绝并保留原任务。

点击「提示词」打开模板库：内置 62 篇，按当前场景过滤；「常用」展示精选示例与收藏，「全部」展示当前场景的全部示例，「我的」管理个人模板。搜索不受常用列表限制，支持「隐藏资产 / FOFA」「证书 / 指纹」「越权 / IDOR」「接口 / OpenAPI」「Nday / CVE」等关键词；草稿按会话保存。选一篇后只填必要字段，其余默认值收在「更多信息」里。

编辑窗口左侧选示例，右侧填写信息、修改正文，也可点「新建」从空白开始。正文始终可直接编辑；手动改写后，不再受原示例必填项限制。「按示例重新生成」会用已填信息替换正文。插入只改聊天输入框，不发送消息、不调用模型。

内置示例改好后，填写名称并点「另存」，即可保存到「我的」；自己的模板可继续编辑，点「保存修改」更新原条目，或用「另存」保留另一个版本。草稿按会话保存，模板保存遇到其他窗口的修改时会提示冲突，保留当前正文。

子代理上限按宿主实际支持范围取整（官方 Desktop 默认 0–8，最高 16），新任务默认最多 2 个活动子实例，可在「更多 → 协作」改为 0–16；超出宿主上限会明确拒绝。只有需要时才分派，不使用时由主代理完成。运行中可调整，原操作额度和截止时间保持；降低上限只禁止后续超限派发，现有助手继续可见并可单独停止。不再提供固定“常规接 Nday”流程；方向切换由用户问题和模型判断决定。

同一处可选择协作方式：

| 选择 | 行为 |
|---|---|
| 自行推进（默认） | AI 在已有范围、资料和预算内自行选择下一步，不要求反复发送“继续” |
| 改动网站数据前问我 | 读取和分析继续；提交、修改或删除业务数据前等待确认 |
| 每个检查步骤前问我 | 先说明这一步要做什么，确认后执行该步骤内的必要调用 |

自由测试和比赛模式在「更多 → 设置」中调整范围、知识查询和用量；协作人数与模型位于「更多 → 协作」。所有修改先形成草稿，点击各自保存后生效。打开或刷新面板只读已保存状态，不启动任务、不续接，也不自动检索知识。缺关键资料、需要登录、范围不清、正常访问失败或被封禁时，先处理受影响的检查。会话上方只有一个「测试结果」页，内部用「执行记录 / 发现的问题 / 测试资料」分类；查看、翻页和导出已有记录不调用模型。

知识查询默认关闭。「更多 → 设置 → 资料」可切换联网优先、本地优先或仅本地，并打开资料管理页。管理页只在用户点击“搜索”时做本地查询；导入、浏览和搜索不会自动发送给模型，也不会打开当前会话的知识开关。关闭后模型侧 `source=reference` 在读取索引、缓存或原文之前就会被拒绝。

回答或发现旁的“整理为知识”只在点击后发送选定正文及必要证据。它可以取消、稍后继续或放弃；结果先进入待检查草稿，保存前必须确认来源和适用条件。独立整理不续接测试，也不消耗主任务工具额度；若桌面宿主缺少一次生成的隔离契约，界面会退回手动编辑而不会启动一个会触发主任务 follow-up 的替代实现。

独立问题可交给助手处理，指定一个或多个已授权资产即可，不要求相同站点或相同研究方向。父子任务共享总预算、取消和写操作归属。IP 被封或正常访问失效时及时停止请求。疑点、已确认问题和交付材料分别记录，响应差异本身不能当作漏洞结论。

普通探索可以直接执行并自动保存实际请求、响应和入口；不要求先建立方法或研究方向。FOFA 原生查询和被动候选整理可只保存候选，不访问候选主机；仍有下一页或配额不足时会保留游标和失败原因。

进度汇报在「更多 → 设置 → 节奏」中独立选择结束时汇总或每阶段简报。共同研判时可在等待节点补充思路，再按当前思路继续。

## 高 DPI 显示

默认跟随 Windows 显示缩放，不强制改写应用比例。需要手动覆盖时，可在启动配置中写入 `interfaceScale`（例如 `1.25`、`1.5` 或 `2.0`）；不写或设为 `0` 时保持系统默认。

## 更新与卸载

更新前完全退出应用，换用新的发布包运行同一安装命令。快捷方式保持原入口与用户数据；重新打开后检查插件版本、MCP 配置和当前任务入口。

每次更新都会在 `%USERPROFILE%\.dsh\backups\desktop-<时间>` 留一份更新前档案：小体积的关键配置
（`package.json`、锁定文件、`cordis.yml`、含 MCP 的 `cordis.patch.yml`），以及更新前的依赖与已启用插件；
安装时加 `--backup-data` 还会整体复制会话与产品数据。

需要退回更新前的状态时，在发布包里执行：

```powershell
node scripts/restore-desktop.mjs            # 列出最近一次备份与回退方案，不写任何文件
node scripts/restore-desktop.mjs --apply    # 完全退出 Desktop 后执行回退
```

回退前会逐字节核对配置副本、并识别数据文件格式，任一不符就停止；执行时先把当前配置另存为
`backups/desktop-pre-restore-<时间>`，所以回退本身也能再回退。回退只还原配置与数据；
装回旧版程序仍需用对应版本的发布包再运行一次安装命令（备份记录里列着当时的依赖与已启用插件）。

卸载可在官方「插件」页进行，或退出后使用桌面自带命令：

```powershell
dsh plugin --profile desktop remove dsh-saker
```

插件卸载不会自动删除历史会话、成果数据库或交付文件。产品使用边界见 [功能说明](features.md)。
