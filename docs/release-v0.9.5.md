# Saker 0.9.5

本版补齐多进程下的工作租约、助手名额和命令幂等边界，并保留 0.9.4 的高 DPI 修正。

### ✨ 新增功能

- 工作租约记录 owner PID 与运行时；过期后只有确认旧进程退出才允许接手。
- 助手名额预留改为 SQLite 事务表，两个 Desktop 进程不会同时抢到最后一个名额。
- 工作台命令增加跨进程 commandId 占用记录；未知执行结果不自动重放。

### 🐛 问题修复

- 修复完成的工作被重新领取的问题；完成态只能创建后继工作。
- 修复释放后的迟到结果把工作重新变回可领取状态的问题。
- 修复旧租约到期但旧进程仍存活时被第二个工作者同时接手的问题。
- 修复跨进程 commandId 同时提交时两个进程都执行一次副作用的问题。

### 🎨 体验优化

- 第二个进程遇到正在执行的命令时返回明确的 `command-in-flight`，提示查询同一命令而不是重试。
- 死进程留下的名额和租约会在下一次准入时清理，不要求用户手工删库。

### ⚠️ 其他变更

- 结果插件升级到 `1.4.4`；已有任务、方法、角色、回执和会话数据保持兼容。
- 对比实验继续暂停；0.7.6 的历史结果仍为双方 64/72、McNemar p=1.0，没有成功率优势。

### ⚠️ 边界

- 本版处理同一结果库上的跨进程准入；外部 CLI/MCP 内部请求仍按实际回执与可见用量计量，不能保证所有隐藏请求都可见。
- 不发布、不 push、不提交 Git。
