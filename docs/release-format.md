# Release 说明格式

Release 用于交付一批完整改进，不对应每次提交。文档、展示图及小修复先积累，常规版本原则上每周至多一次；没有准备好则顺延。紧急修复或用户明确要求交付时可提前发布，具体约定见 [开发与发布](development.md)。

标题为 Saker v<版本号>，正文按以下顺序描述用户可见的变化：

先用一小段说明本版主要改变了什么、用户怎样使用。以与上一公开版本相比的实际变化为准，不按最后一个提交或最后一轮修复来写。集中交付中的入口重组、流程调整、能力增补与功能退出都要说明；不能把一整轮产品调整写成“新增功能：无”后再堆几十条修复。

每条围绕用户能做什么、操作怎样变化来写；同一功能的多次修补合并描述。已有功能的重做明确写“重做”“整合”或“调整”，不冒充首次新增。常驻提示词、资料、知识和助手机制的变化说明使用方式，不把内部函数、诊断变量或实现细节作为主要内容。

```markdown
### ✨ 新增功能

- 新能力及用途。

### 🐛 问题修复

- 具体问题和修复后的行为。

### 🎨 体验优化

- 界面、操作流程或效率的变化。

### ⚠️ 其他变更

- 兼容性、迁移注意事项和产品限制。
```

没有变化的栏目可写「无」。正文不包含测试数量、运行结果、验收截图、开发对话、内部目标或开发记录链接。适用版本及真实功能限制可以保留，不夸大能力。

正文源文件为 docs/release-v<版本号>.md。更新历史发布说明仅修改正文，保留标签、发布状态和附件。安装包仅携带用户文档白名单。
