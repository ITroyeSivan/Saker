## 二、完整目标的剩余验收项

不能因为上面的局部检查通过就声称“项目无错误”。以下仍属于原目标。

1. **交付闭环**：已测无效项只有资产/检查/状态；详细原因留本地。有效漏洞交付可用利用脚本或完整利用方法，并与实际证据、前提和方法版本对应。仓库链接不能替代交付。须在成果工具、保存数据、导出与桌面页面贯通。
2. **常规测试降本**：传统信息收集、服务分组、漏洞发现与利用验证仍完整；共享资产、指纹、请求、身份、方法、已测记录；批处理结果摘要与必要证据按需读取。须用相同目标、模型、预算验证发现量与花费。
3. **后台/API 0Day**：门户有限定位入口；真实后台/API 功能输入才进入深入研究；无有效入口明确结束入口定位。须对登录态、多身份、接口分组、正常对照、反证和已知/变体/疑似未公开分类做行为验证。
4. **情报维护**：定期增量与定向临时补查结合；逐源分页、水位、失败退避、完整/部分同步、撤回/修改、来源覆盖与延迟；轻量线索长期存储，审核的方法包分层保存，代码按需缓存。GitHub 公告不等于 PoC/HW 项目覆盖；公众号/CNVD 无稳定接口时保持能力状态真实。
5. **资产—漏洞—动作排序**：当前仍需进一步从候选排序转成资产证据驱动的执行队列。已满足、不适用、未知三个状态；新/通用高危候选与历史高价值候选并存，避免热门单产品占满。
6. **桌面端最新宿主**：核对并固定实际最新 dsh 版本；桌面官方插件安装/升级边界；设置页、工具清单、提示注入、异步问答、模型目录和重启恢复实际验证。旧 Web 安装脚本不得直接改桌面 profile。
7. **真实宿主与交付产物**：版本提升、打包卫生、安装字节一致、真实 defineTool/schema、调用结果、模型 transcript 与桌面运行证据。编译成功和测试桩不能替代这些检查。
8. **效果基准与指标**：正确统计独立资产/方法/证据，区别产品命中、有效漏洞、未知和阻断；验证有价值漏洞召回率、误报、查询次数、模型调用数、token/耗时，不承诺全量情报或必出漏洞。
