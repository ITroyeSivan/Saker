# Saker dirsearch 输出淹没：扫到了但模型看不见（2026-09-19）

## 怎么发现的

当天最后那轮端到端回归（`session-c5ee66df…`）只登记了 **2 条** finding，
而上午那轮登记了 4 条 —— 少了 `/.git/config` 未授权可读（靶标里植入的两条
marker 之一）。同一个靶标、同一句提示，为什么少了一条？

翻工作区，模型自己在覆盖矩阵的「未排除面」里写得很清楚：

> 目录枚举：dirsearch 跑了 10761 词但**结果流未落盘（仅进度条）**，
> 已用人工 25 个高价值路径替代，**未做全字典扩展名地毯**。

模型**如实登记了盲区**，没有假装扫过 —— 但盲区本身不该存在。

## 根因：进度条把命中挤出了预览

看 `artifacts/tool-output/dirsearch-*.txt`：

```
807,347 字节
第 1 行就是几万个进度条片段：
[     ]  0%      4/10761   20/s  job:1/1  errors:0[     ]  0%   7/10761 ...
...
命中行埋在第 37,732 字节处
文件末尾： [####################] 100% 10761/10761  Task Completed
```

dirsearch 默认把进度条写到输出流，且用 `\r` 回车覆盖。**重定向到文件时这些
回车不生效**，于是几万个进度片段连成一整行，真正的命中被夹在中间。

而工具返回给模型的预览只取**开头 6000 字**（`previewChars: 6000`）——
那 6000 字全是进度条。模型拿到的就是：

```
dirsearch 完成（exit 0，输出 807347 字符；全文 artifacts/tool-output/...）
  _|. _ _  _  _ _|_    v0.4.3
 Extensions: js, json, txt | HTTP method: GET | Threads: 10
 Wordlist size: 10761
 Target: http://127.0.0.1:18081/
 [     ]  0%      4/10761   20/s ...
```

**扫描器扫到了 `/.git/config`（200），模型没看见，于是漏报。**

这不是 dirsearch 的 bug，是我们的封装漏了静默参数：注册表里
`katana`（`-silent -nc`）、`afrog`（`-silent -nc`）、`subfinder`（`-silent`）、
`whatweb`（`--color=never`）都带了静默/去色默认参，**只有 `dirsearch` 的
`defaults` 是空数组**。

## 修复（dsh-scanner-tools 1.0.15）

`dirsearch` 默认参数加 `-q`（quiet-mode）+ `--no-color`。

## 验证

### 1. 同一份字典，同一目标，直接比输出体积

```
不加 -q ：807,347 字节（命中埋在 37KB 处，被进度条包围）
加 -q    ：    260 字节 / 3 行
  [13:40:44] 403 -    68B - http://127.0.0.1:18081/admin
  [13:40:45] 200 -    45B - http://127.0.0.1:18081/health
```

### 2. 走真实模型 + 真实工具路径（决定性验证）

起真实宿主，让模型只做一件事：「调用 `dirsearch_dirs` 扫 `http://127.0.0.1:18081`，
把返回里出现的所有命中路径原样列出」。

工具返回（**336 字符**）：

```
dirsearch 完成（exit 0，输出 336 字符；全文 artifacts/tool-output/dirsearch-20260919T05452214-85ee5245fad6.txt；证据 E1）
[13:45:14] 200 -    77B - http://127.0.0.1:18081/.git/config
[13:45:15] 403 -    68B - http://127.0.0.1:18081/admin
[13:45:18] 200 -    45B - http://127.0.0.1:18081/health
```

模型最终回答（逐字）：

```
[13:45:14] 200 -    77B - http://127.0.0.1:18081/.git/config
[13:45:15] 403 -    68B - http://127.0.0.1:18081/admin
[13:45:18] 200 -    45B - http://127.0.0.1:18081/health
```

**`/.git/config` 现在第一时间就到了模型手里。** 落盘产物也从 807KB 降到 6 行。

顺带确认「目标须登记」这道闸是有效的：模型第一次调 `dirsearch_dirs` 时工作区还没有
`assets.md`，工具直接拒绝并给了修复提示（`先完成测绘阶段（pentest Gate P1）`），
模型补了资产基线后重试成功 —— 代价只有 1 次额外调用。

### 3. 回归锁

新增断言：`buildArgs(dirsearch)` 必须包含 `-q` 与 `--no-color`。
`dsh-scanner-tools` 单测 `79/79`。

## 影响面

这条缺陷的形状是**最危险的一类**：工具"成功"（exit 0）、证据"落盘"了、
模型还如实登记了盲区 —— 每一步看起来都对，**唯一的问题是命中没进模型的眼睛**。
在真实护网里表现为「跑了一堆扫描器但什么都没发现」。

同类风险已顺手核对：其余 12 个封装工具都带静默/去色默认参，只有 dirsearch 漏了。
