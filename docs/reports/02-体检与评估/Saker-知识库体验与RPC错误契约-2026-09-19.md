## 三、真正的硬伤：RPC 失败回字符串 → 客户端 Promise reject → 界面白板

点开一条 Exploit-DB 命中，出现的是：

**空白详情区 + 按钮卡在「保存中…」+ 一句错误都没有。**

抓客户端未处理拒绝：

```
TypeError: connection: invalid server-response result
    at parseConnectionResponse (.../dsh-client-connection/client.js)
```

翻宿主连接层源码 `packages/client/connection/src/client/rpc.ts`：

```ts
if (result.ok === true) { … }
if (result.ok !== false || !isRecord(result.error)) {
  throw new TypeError('connection: invalid server-response result')
}
const error = result.error
if (typeof error.code !== 'string' || typeof error.message !== 'string' || !isRecord(error.details)) {
  throw new TypeError('connection: invalid server-response failure')
}
```

**失败必须是 `{ok:false, error:{code,message,details}}` 结构体。**

而 `dsh-knowledge-hub` 的 dispatch 写的是：

```js
const fail = (error) => ({ ok: false, error })   // ← error 是字符串
```

于是**任何**失败路径（路径越界、文件不存在、只读层写入、导入失败……）
都会让宿主回一个不合规的 `result`，客户端 `parseConnectionResponse` 抛错 →
`rpc.call` 的 Promise **reject** → 客户端 `.then(...)` 永不执行 →
`busy` 永远是 `true` → 界面卡在「保存中…」+ 白板。

这不是 EDB 特有问题，而是**知识库所有错误路径共同的表现形式**。

同源排查（哪些插件注册了连接层 RPC）：

| 插件 | 失败形状 | 结论 |
|---|---|---|
| skill-browse | `{code,message,details}` | ✅ 正确 |
| method-stack | 结构化 | ✅ |
| sec-config | 结构化 | ✅ |
| mcp-studio | 结构化 | ✅ |
| **knowledge-hub** | 字符串 | ❌ 修 |
| **webshell-mgr** | 字符串 | ❌ 修 |

### 修复

1. `knowledge-hub`：`fail()` 与连接层 catch 分支都改成结构化错误；
   客户端 `errText()` 同时接住字符串与对象（否则把对象塞进 React 子节点会再抛
   `Objects are not valid as a React child`）。
2. `webshell-mgr`：RPC 块加 `rpcFail()`，9 处字符串错误全部替换；
   客户端加 `errOf()`，7 处 `r.error` 直接当文案的地方改掉。
3. 回归锁：
   - knowledge-hub 断言失败必须是结构化对象；
   - webshell-mgr 断言 RPC 块里**不得再有** `ok: false, error: "` 字面量，
     且客户端必须走 `errOf`。
