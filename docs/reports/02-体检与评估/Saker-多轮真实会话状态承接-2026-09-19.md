# Saker 多轮真实会话：状态承接验证（2026-09-19）

## 为什么测这个

护网的常态不是"一句话跑完"，而是**同一场战役里连续下指令**：
先侦察、再挑一个入口验证、再补别的面。之前所有真实模型测试都是**单轮**，
没人验证过"第 3 轮还认不认第 1 轮写下的东西"。

## 做法

真实模型（`deepseek-flash`，经用户 8788 代理）+ 真实宿主 + 本机授权靶标
`http://127.0.0.1:18081`，**同一个会话连下三轮**（用新写的
`_ref/tools/drive-turn.mjs` 往已有会话续轮，`drive-session.mjs` 只能建新会话）：

| 轮 | 我给的指令 | 关键约束 |
|---|---|---|
| 1 | 只做侦察与入口面盘点，写好资产基线 | **明确"不要做漏洞验证，留到下一轮"** |
| 2 | 自动推进（auto-advance 开工提醒） | 插件自动插入 |
| 3 | 挑上一轮盘点里**最有价值**的入口做验证 | **"只做这一个，不要扩面"** |
| 4 | 自动推进 | 插件自动插入 |

## 结果：承接住了

**第 3 轮确实是在吃第 1 轮的成果，而不是重新推导。** 证据：

1. 第 3 轮登记的范围 `t1..t5` 与第 1 轮的侦察范围一致，
   其中 `t5` 直接写着「资产基线 assets.md 与 evidence-index」；
2. 第 3 轮验证的目标 `/admin` 是第 1 轮入口面盘点里的条目，不是重新扫出来的；
3. 第 3 轮覆盖标记的理由明确引用前一轮的证据链：
   `/admin 通过客户端可控 role 参数无凭据取得 admin 控制台（基线 403 → 差分 200 + marker 回显）`；
4. 第 3 轮**遵守了"不扩面"**：水平越权那一格直接判 `na`，理由写
   「本轮定向口径：用户明示只验证 /admin 的 role 参数这一个入口，不扩面；未指定项不补测不欠账」。

## 这一轮的工具选择（顺带观察）

同一句"侦察+验证"的意图，这次模型**主动用了内置扫描器**：

```
httpx_probe=1  wafw00f_detect=1  ffuf_fuzz=2  dirsearch_dirs=2
```

而上午那轮几乎全靠 `pwsh` 跑 CLI。说明**工具选择随任务措辞浮动**——
两轮都完成了任务，所以这属于"可选路径"而非缺陷（细节见
《Saker-工具选择行为观察》）。

## 上下文增长

按轮统计会话日志增量（含该轮全部事件）：

| 轮 | 日志增量 | 工具调用 |
|---|---:|---:|
| 1 侦察 | 780 KB | 39 |
| 2 自动推进 | 39 KB | 1 |
| 3 验证 | 749 KB | 30 |
| 4 自动推进 | 41 KB | 1 |

累计：assistant `875 KB` / tool-result `178 KB` / user `276 KB`。

两点值得记下：

- **tool-result 只占 178 KB**：工具结果封顶预览（32K 裁剪 + 全文落盘）确实在起作用，
  否则光是几次扫描的原始输出就能把上下文顶满。
- 宿主上报的 `contextWindow = 1000000`，1.3MB 级会话离上限还很远；
  真正的有界增长证明仍来自 30/100/300 轮 mock 审计（release gate 的 `--context`）。

**观察（未改）**：auto-advance 会在每轮实质工作后插入一个"开工提醒"轮，
本会话 4 轮里有 2 轮是它。对长战役这是"别停下"的正向推力，代价是
每轮实质工作多一次模型往返。是否值得，取决于用户更喜欢"自动推进"还是"手动下一条"。

## 顺带修的量具

`_ref/tools/read-session.mjs` 的"收口"判据原来是「存在 turn/end 且静默 20s」，
多轮会话里第 N 轮刚结束、第 N+1 轮已经开跑时会**误判为已收口**（本次实测踩到，
第 3 轮进行中就被报成结束）。现在改成「**最后一条事件**必须是 turn/end」。
