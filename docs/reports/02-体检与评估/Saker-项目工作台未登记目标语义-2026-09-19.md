# Saker 项目工作台「未登记目标」语义修复（2026-09-19）

## 问题来源

下午那轮真实模型的端到端回归（见《Saker-端到端渗透回归复验-2026-09-19》）跑完后，
用 `scripts/project-status.mjs` 复盘工作区，看到：

```
project: e2e-model-ws
goal: (unregistered)
criteria: 0/0 closed
intents: 0/0 closed
...
attention: 0
```

模型这一轮**没做开工登记**（`operation-state.json` 里 `goal` 为空、`criteria` 为空），
直接干活干到 `operation_conclude` 收口。

翻工作台客户端代码发现问题：

```js
snapData.hasLedger === false
  ? "本工作区还没有 operation-state.json（尚未登记目标契约）……"
  : null
...
criteria.met + "/" + criteria.total   // 显示 "0/0"
...
criteria.openItems.length ? <表> : "准则已全部收口"
```

**只区分了「台账文件不存在」，没区分「台账存在但目标没登记」。**
于是一个从没立过标准的项目，页面上是「`0/0` 准则已收口」——
读起来像"全部做完"，实际是"什么都没登记"。这正是本轮一直在抓的那类形态：
**失败长得像成功**。

## 修复（dsh-stage-gate 1.7.2）

服务端 `project-snapshot.mjs` 增加 `goalRegistered` 字段；台账存在但 goal 为空时，
往 `attention` 里塞一条 `目标契约：尚未登记目标契约（operation_goal）——准则 0/0 不等于已收口`。

客户端 `client.js` 相应分叉：

| | 修复前 | 修复后 |
|---|---|---|
| 指标卡 | `0/0` 准则已收口 | **`未登记` 目标契约**（告警色，不进 `0/0` 分母） |
| 需要处理 | 无 | 多一条「目标契约」 |
| 目标与准则区 | 「准则已全部收口」 | 「目标契约未登记，因此没有准则可收口 ——「0/0」不代表已完成，请先让模型调 operation_goal。」 |

台账文件**完全不存在**时的原有提示保留不变。

### 回归

`dsh-stage-gate` 单测 `249/249`，其中新增 3 条：

- 已登记目标时不误报「目标契约」缺失；
- 台账在但没登记目标 → `goalRegistered === false`；
- 没登记目标时必须进 attention（不能显示成健康 `0/0`）。

### 正常路径回归（防止修一个坏一个）

改的是客户端分支逻辑，所以又把**已登记目标**的那份真实数据（目标 + 3 条准则 +
3 条意图，含 succeeded / interrupted / 结果冲突）在同一个浏览器里点了一遍：

```
9 需处理 | 1/3 准则已收口 | 3 未收口意图 | 3 任务 | 1 结果冲突 | 2 报告产物

需要处理
  未收口准则：g2：SQL 注入拿到 whoami 证据
  未收口准则：g3：覆盖矩阵每格有终态
  未收口意图：i1 / i2 / i3（succeeded / succeeded / interrupted）
  中断任务：i3：后台端口扫描（心跳过期）
  任务结果冲突：i2 … （终态 succeeded，收到 1 条不同结果；最近 succeeded→failed）
  ...
目标与准则
  对 demo 靶站完成授权渗透并出报告
```

断言：`hasUnregistered=false`、`hasGoalWarning=false`、`0/0` 告警**没有误报**、
指标仍是 `1/3 准则已收口`、`data-slot-error=0`、无横向溢出。
截图：`_ref/shots/workbench-with-goal-1600.png`。

> 顺带记一个操作细节：用 CFT 打开会话时，直接用 URL 进不去具体会话
> （页面停在「选择一个工作区」）。可行做法是把 `localStorage` 的
> `dsh.sessions.current` 写成 `{"sessionId":"<id>"}` 再 `goto` 刷新。
> 另外 `[role=tab]` 会匹配到第一个「对话」标签，必须按元素中心坐标点击才点得准。
