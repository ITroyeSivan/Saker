# Saker 状态闭环与有界发现修复（2026-09-19）

## 问题一：复核结论被静默改写

真实靶标任务中，独立复核把一条路径归一化发现降级为“疑似”，模型调用了
`redteam_finding_update(status=suspect)`，工具返回成功，但台账仍显示 `pending`。

根因在 `dsh-redteam-results/lib/store.js`：状态清洗用 `cleanEnum` 对不在模式词表内的值
静默回落；渗透模式词表没有 `suspect`，所以写库变成了 `pending`，工具回执却无法暴露这件事。

修法：

- 渗透/代审词表加入 `suspect`，语义限定为“静态或侧信道线索成立，但影响链未闭环/只能部分复现”；
- `registerFinding` 与 `updateFinding` 对不适用状态显式报错，不再静默回落；
- `verifiedAt` 只在当前状态仍为 `verified`（或已修复 `fixed` 保留可追溯历史）时有效；
  复核挑战到 `suspect/false-positive/pending` 会清空旧验证时间，避免“疑似”同时带验证时间；
- 状态指南、字段词典、报告草稿状态标签和人工复核弹层同步支持疑似态；
- 人工复核弹层不再硬编码只有一个负面选项，按模式列出全部合法非验证终态。

验证：

- `dsh-redteam-results`：`78/78` 通过，`6` 个上游缺失模式用例跳过；
- 真实模型复验 `session-ea44dcbb-a072-4f59-8b55-5eebab96b58d`：
  工具回写后数据库实读 `status=suspect`、`verifiedAt=""`，复核注记完整落库。

## 问题二：有界发现仍被追加轮次

上一轮有界发现验收使用了“至少一个/找到一个”表述；本轮换成
“有界发现 + 只选一个 + 立即收口 + 不要扩展全量扫描”后，旧检测漏判：

- `dsh-auto-advance` 仍注入开工提醒；
- finding 登记后 `dsh-attack-atlas` 注入覆盖矩阵提醒；
- 同一任务被追加到第 2、3 个模型轮次。

修法：

- 扩展有界识别词面，覆盖 `有界发现`、`只选一个`、`先找一个`、
  `不要扩展全量扫描` 等组合表达；
- 增加完整评估反向判据：出现“全量/全面/覆盖矩阵/所有漏洞”但没有明确
  “至少一个/有界/只找一个”等交付上限时，不判有界，避免误伤正式覆盖；
- `dsh-attack-atlas` 对真实任务消息做同样的有界判定；有界任务仍可自动点亮
  finding 对应事实格，但不再注入“剩余 14 格未终态”的覆盖提醒。

验证：

- `dsh-auto-advance`：`80/80`；
- `dsh-attack-atlas`：`105` 适用通过，`3` 个上游缺失模式用例跳过；
- 同一模型提示复验 `session-ea44dcbb-a072-4f59-8b55-5eebab96b58d`：
  仅 `1` 个模型轮次，开工提醒 `0`、覆盖提醒 `0`；
  模型仍完成登记、`suspect` 回写、`operation_conclude` 和正常收口。

## 附带修复：代理 SSE 心跳污染 data 行

真实发现任务第一次运行在第二轮被 `Unterminated string in JSON` 中断。现场不是靶标或工具问题，
而是代理的 SSE 帧边界处理：

- 上游把一条 `data:` 行拆成多个 TCP chunk；
- 代理转发半个行后进入 keepalive 分支，插入 `: keepalive`；
- 该注释落在 `data: {"...","ob` 后面，变成非法 JSON。

现有代理目录内已有复现脚本 `test_keepalive_frame_split.py`；修复前实跑为 `FAIL`，
输出中包含 `"ob: keepalive` 污染指纹。修复为“流式响应先按完整行缓冲，只有看到换行才向客户端转发；
半行留在代理 pending 区，因此心跳可以插在安全行边界”。

验证：

- `test_keepalive_frame_split.py`：`PASS`，可解析 `data:` 行 `2`、失败 `0`，心跳 `2`；
- `test_live_stream_smoke.py`：真上游流式冒烟 `PASS`，收到 `35` 个可解析 `data:` 行，
  `0` 解析失败，流正常收尾且正文可见；
- 使用隔离端口 `8789` 跑真实模型链路（不杀用户在 `8788` 上的进程）：
  `session-9819938a-967b-4f25-a35a-e9713a6c6fcf` 一轮内自主发现
  `/admin?role=admin` 未授权访问，独立子代理复核，台账实读
  `high / verified / impact`，完成攻击面点亮、链路对账与收口；
- 验证完成后隔离 home 的模型端点已恢复为 `http://127.0.0.1:8788/v1`，
  临时 `8789` 进程和测试宿主已关闭。

`8788` 用户实例已在无活动连接时按 PID 重启到修复版：新 PID `17168`、代码指纹
`2ea760469d96`。重启后直连 `8788` 的真实流式请求复验为 `4924` 字节、
`data_parse_fail=0`、无 keepalive 污染，`/__health` 返回 `ok=true`。
