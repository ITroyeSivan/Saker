# Saker 扫描器真实调用验证（2026-09-19）

## 目的

验证 pentest 模式里的本地扫描器封装不是只有单测，而是能被真实模型调用、解析路径、执行本机二进制、落盘证据并返回可用于下一步判断的命中摘要。

## katana 与 dirsearch

本地授权目标：`http://127.0.0.1:18081`

模型按显式指令调用：

- `katana_crawl`：成功，exit 0，证据 `E1`；该夹具入口无链接，因此按事实报告 0 条 URL。
- `dirsearch_dirs`：成功，exit 0，证据 `E2`，4/4 请求无错误。

dirsearch 命中：

```text
200  /.git/config
200  /health
403  /admin
```

模型没有把这些命中直接写成漏洞，而是标注为“发现，未验证”。

### katana 空输出根因

后续把夹具改成含 `/health`、`/admin?role=user`、`/static/app.js` 的 HTML 页面后，katana 仍然 0 输出。对照官方 `katana -h` 确认：

```text
INPUT:
  -u, -list string[]  target url / list to crawl
```

真正的根因是参数模型把 target 当成位置参数，而 katana 只接受 `-u <url>`。修复后：

```text
katana -u http://127.0.0.1:18081 -d 1 -rl 5 ...
```

复测输出 4,562 字符，发现：

```text
http://127.0.0.1:18081
http://127.0.0.1:18081/admin?role=user
http://127.0.0.1:18081/health
http://127.0.0.1:18081/static/app.js
```

evidence `E2`。

## ffuf 回归发现

第一次真实调用 `ffuf_fuzz` 时发现：

- 工具本身成功，证据也正确落盘。
- 但回执只有 evidence ID，没有命中路径。
- 原因是 `ffuf` 用 `-o` 写 JSON，stdout 被静默；原解析器没有回读该文件。

修复后，`ffufParse` 从 `-o` JSON 抽回：

- 状态码
- 响应大小
- URL
- 命中数量和前 8 条预览
