# Saker 报告导出统计口径修复（2026-09-19）

## 为什么要走这一遍

交付物是护网的最后一公里：发现再多，导出的报告里数字错了就是白干。
用户此前明确要求「最后测试的时候用浏览器实际测试一下，不要只看代码」，
所以这一轮不读代码，直接在 Chrome for Testing 里把导出点一遍。

## 浏览器实测（CFT 9333）

会话 `session-66517d28…`（工作区 `_ref/e2e-model-ws`，当天端到端回归的 4 条 finding）：

1. 打开「redteam 成果」标签页 → 实际渲染 18 条成果、状态分布、任务流水。
2. 切到「渗透测试模式」列表视图 → 工具栏出现「导出 ▾」。
3. 打桩 `URL.createObjectURL` 截下 blob（**不靠下载目录**，直接拿到导出内容）。
4. 点「导出 ▾」→「结构化报告（JSON）」。
5. 取回 blob 交给仓库自带的校验器：

```
ok   export-structured.json schema=saker.redteam.report.v1 version=1 migrated=false warnings=0
```

导出内容本身是好的：17 条 finding 全在，今天那 4 条状态都是 `verified`。

**但统计块是错的。**

```
stats.bySeverity : {"critical":1,"high":5,"medium":5,"low":6}     ← 对
stats.byStatus   : {"pending":2,"suspect":2,"verified":13,...}    ← 对
stats.byEvidence : {"impact":0,"confirmed":0,"partial":0,"unknown":0,"undefined":null}   ← 全 0 + 幽灵键
```

同一个 JSON 里，每条 finding 都带着 `evidenceLevel: "partial" / "impact" / "confirmed"`，
统计却数出 0 条。交付出去的报告会写着「证据等级：impact 0 / confirmed 0 / partial 0」。

## 根因

`plugins/dsh-redteam-results/lib/store.js`：

```js
export function computeStatsAll(store, mode, { from = "", to = "" } = {}) {
	const rows = store.listGlobalMode.all(mode)          // ← 裸 DB 行，snake_case
		.filter((row) => (from === "" || row.created_at >= from) ...);
	return statsOf(rows, mode);                          // ← statsOf 读的是 camelCase
}
```

而 `statsOf` 里：

```js
byEvidence[f.evidenceLevel] += 1;   // f.evidenceLevel 是 undefined
```

`COLS` 是 `session_id, id, ..., evidence_level, ...` 这样的**下划线列名**，
所以全局路径上 `f.evidenceLevel` 恒为 `undefined` → `byEvidence[undefined] += 1`
→ `undefined + 1 = NaN` → `JSON.stringify` 把 NaN 写成 `null`。
这正好解释了那个 `"undefined": null`。

同一条路径上还有三个字段被同样地读空（只是没那么显眼）：

| 字段 | 裸行里的名字 | 后果 |
|---|---|---|
| `evidenceLevel` | `evidence_level` | 证据等级四档全 0 |
| `sourceOrigin` | `source_origin` | `bySource` 全部算成 `manual` |
| `auditMode` | `audit_mode` | `byAuditMode` 永远为空 |
| `updatedAt` | `updated_at` | `lastAt` 永远为空串 |

会话内统计（`computeStats`）走的是 `rowToFinding()` 归一后的数据，所以**一直是对的**——
这也解释了为什么这个 bug 只在「跨会话/模式级」的导出里露出来，单测没照到。

## 修复（dsh-redteam-results 1.0.18）

1. `computeStatsAll` 先过 `rowToFinding()` 再统计（与会话内路径同源），
   过滤器改用归一后的 `createdAt`。
2. `statsOf` 加护栏：`byEvidence` 未知值归 `unknown`、`bySeverity` 用 `?? 0`，
   任何越权值都不再产生 `NaN` / 幽灵键。

回归新增 1 条：跨会话统计必须认出 `impact` / `partial`，
不得出现 `undefined` 键，`bySource` 计数正确。
