# Saker 知识库阅读体验修复（2026-09-19）

## 问题

知识库的目录分组和检索已经可用，但打开文章后仍然是窄列原始 Markdown：

- 左侧目录与右侧正文同时占位，正文只有约半栏宽。
- 包内文档、导入文档都直接显示源码，标题、列表、代码块和链接难以扫描。
- YAML frontmatter 与正文混在一起；800px 视口下长 frontmatter 还会把正文挤成竖排单字。

这不是功能缺失，而是实际使用时的阅读效率问题。护网现场需要快速查 payload、命令和利用链，原文源码视图过慢。

## 修复（dsh-knowledge-hub 0.3.6）

1. 打开文件时隐藏目录/检索列表，正文独占内容区，并保留 `← 返回列表`。
2. 增加 `预览 / 源码` 切换：
   - 包内文档默认预览。
   - 用户/导入层默认源码，便于直接编辑。
3. 新增安全的 React Markdown 预览，不经过 `innerHTML`：
   - 标题、段落、列表、引用、代码块、行内代码、链接、强调。
   - 链接只接受 `http/https`，其余作为普通文本。
4. YAML frontmatter 容错识别并压缩成键值区；只接受合法 YAML 键名，不再把正文冒号行误当元数据。
5. 800px 视口下元数据和正文均正常换行，无横向溢出。

## 0.3.7 追加修复：目录状态与来源内筛选

### 实测缺陷

在真实 1600x1000 页面中，PATT 来源有 `66` 个分类。展开 `Command Injection`，将目录滚动到 `843px`，打开其中 `README.md` 后再返回：

- 展开状态丢失，`Command Injection` 重新折叠；
- 滚动位置回到 `0`。

根因是打开文章时 `Page` 直接不渲染 `TreeSection`，返回时组件重新挂载，所有本地状态归零。

### 修复

1. 打开文章时仅把目录列 `display:none`，让 `TreeSection` 保持挂载；返回后保留展开状态与滚动位置。
2. 每个来源目录增加“筛选当前来源的分类或文件…”输入框，支持清除。PATT 输入 `Command` 后从 66 个分类缩减为 `Command Injection` 一项。

### 浏览器复验

- 展开 `Command Injection`、滚到中段、打开 `README.md`、返回后：
  - `Command Injection` 仍为展开状态；
  - 目录滚动位置保留在 `886.5px`，未回顶；

## 0.3.9 追加修复：证据路径不再让模型自己找

### 模型级复验暴露的问题

让真实模型只查本地离线资料回答 fastjson 反序列化问题，并要求给出实际读取的绝对路径。第一版虽然能命中正确的 `components/java-framework-vulns.md`，但 `knowledge_read` 只返回逻辑路径：

```text
[bundle] components/java-framework-vulns.md
```

模型为了落实磁盘路径，又额外调用 `glob/grep/pwsh` 扫描文件系统。观察到的会话 `session-9307ea5f-00d2-4db0-855b-9895c6fa1074` 共产生 `31` 次工具调用、输入约 `75,175` tokens。

### 修复

- `knowledge_read` 返回值增加 `root` 与 `absPath`。
- 模型可见的 render 直接输出实际文件，例如：

```text
[bundle] components/java-framework-vulns.md 行 1-80
文件：C:\Users\12201\.dsh\profiles\web\node_modules\dsh-saker\preset\pentest\refs\components\java-framework-vulns.md
```

- `knowledge_list` 的各层目录摘要也带 `root=<磁盘路径>`。
- 新增回归断言：精读返回的 `absPath` 必须存在，且 render 必须包含它。

### 修复后复验

同一题、同一低思考强度，会话 `session-4604cb51-62b2-4c15-be31-dc681db4204c`：

- 工具调用从 `31` 次降到 `14` 次；
- 输入从约 `75,175` tokens 降到约 `49,168` tokens；
- 模型的精读结果直接包含 bundle 的真实绝对路径；
- `dsh-knowledge-hub`：`106/106` 测试通过。

## 0.3.10 追加：来源筛选跨折叠目录查找

### 问题

来源筛选原先只匹配已经加载到浏览器的子树。PATT 有 66 个分类且默认折叠，
用户输入 `Log4Shell` 时目录里明明有 `CVE Exploits/Log4Shell.md`，页面却可能显示无结果——
必须先手动展开对应分类，筛选才“看得到”它。

### 修复

- 检索层新增来源限定：先多取候选再按 `bundle / patt / user / import` 过滤，
  避免其它来源的高分结果先把候选位占满。
- 知识库页面的来源筛选改为调用现有离线 FTS5 索引，得到跨折叠目录的扁平文件命中；
  不再要求用户逐层展开。
- 点击扁平结果仍按真实来源和相对路径读取，保留原有预览、源码、绝对路径和写层约束。
- 模型工具 `knowledge_search` 同时支持可选 `source`，模型也可直接限定来源层检索。

### CFT 复验

- 在 PATT 默认折叠状态下输入 `Log4Shell`；
- 页面直接显示 `PATTCVE Exploits/Log4Shell.md:1`；
- 点击后成功打开该文件，预览、源码和返回列表控件均可用；
- `data-slot-error=0`，无横向溢出；
- 真实索引上来源限定检索延迟：`patt` 平均 `13.1ms`、`import` 平均 `13.2ms`
  （全来源平均 `40.6ms`），250ms 输入防抖不会造成可感知卡顿；
- `dsh-knowledge-hub`：`108/108` 测试通过。
