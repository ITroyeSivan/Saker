# Saker 端到端渗透工作流实测（2026-09-19）

## 目的

验证 Saker 不是“每个工具单独能用”，而是真实模型可以从授权目标探测、取证、登记、独立复核到图谱回写完整闭环。

## 靶机

本地授权夹具：`http://127.0.0.1:18081`

- `/.git/config`：返回仓库配置与 `SAKER_GIT_CONFIG_MARKER`。
- `/admin`：无参数返回 403；`role=admin` 返回 200 与 `SAKER_IDOR_E2E_MARKER`。

夹具脚本：`_ref/tools/synthetic-pentest-target.mjs`。

## 模型会话

会话：`session-a1662eaf-ef4a-4bcf-99e7-b6cddfb54712`

用户只要求完成一轮授权本地验证，没有点名具体 MCP 工具。模型实际调用：

- `mcp_search`
- Burp MCP `send_http1_request`
- Yakit MCP `do_http_request`
- `redteam_atlas_target`
- `redteam_finding_register`
- `subagent`
- `redteam_finding_update`
- `redteam_coverage_mark`

模型没有使用 shell、curl 或外部网络。

## 发现与证据

| ID | 问题 | 等级 | Marker | 状态 |
|---|---|---|---|---|
| `pentest-2` | `/admin` 的 `role` 参数越权，无凭据 `role=admin` 即进入管理员控制台 | high | `SAKER_IDOR_E2E_MARKER` | verified |
| `pentest-1` | `/.git/config` 未授权敏感信息泄露 | medium | `SAKER_GIT_CONFIG_MARKER` | verified |

`/admin` 对照：

```text
GET /admin              -> 403
GET /admin?role=user    -> 403
GET /admin?role=1       -> 403
GET /admin?role=admin   -> 200 + SAKER_IDOR_E2E_MARKER
```

复核由独立 DSH 子代理完成，二次评级与初判一致。`pentest-2` 复核还构造了多组对照，排除了 Cookie/会话态、大小写、trim、参数通道和参数污染等替代解释。

### CFT 页面实测

用 Chrome for Testing 打开该真实会话后：

| 页签 | 实际显示 | 结论 |
|---|---|---|
| redteam 成果 | 2 条已验证 finding，1 高危 + 1 中危 | 结果台账正确 |

## 项目工作台职责评估

代码和实际数据源确认：项目工作台不是 redteam 视图的重复页。

| 页面 | 数据源 | 职责 |
|---|---|---|
| 项目工作台 | 工作区 `operation-state.json`、`gate-log.md`、`evidence-index.md`、`scan-reconcile.md`、`reports/` | 项目契约、准则/意图/任务、待处理项、产物索引 |
| redteam 成果 | `redteam-results/results.db` | finding 台账、验证状态、报告导出 |
| AttackAtlas | `attack-atlas/atlas.db` | 目标、覆盖矩阵、攻击链 |
| 战役记忆 | `campaign-memory/memory.db` | 跨会话经验与反馈 |

项目工作台明确只读工作区文件，不读其他插件 SQLite，避免隐式 schema 耦合；跨库汇总由离线 `scripts/project-status.mjs` 负责。因此四者职责可区分：项目状态、结果台账、覆盖/链路、长期经验。

## 结论

本轮真实模型工作流通过，Saker 已证明具备：

- 多 MCP 通道主动选择与双通道取证。
- 发现登记、独立复核、二次评级和状态回写。
- 成果库、目标、覆盖矩阵和链路节点的真实持久化联动。
- 对未测格子的边界保持，不把未知状态伪装成已验证。
