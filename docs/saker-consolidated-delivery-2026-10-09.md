## ARTEX 的实际做法与借鉴边界

此前核对的是 ARTEX 提交 `e6ec56999175509551a1e43a3ee3b053d0941bd9`；本次重新读取其公开源码与 README。它将规划、意图领取、worker 执行、过程记录、证据、发现和复测围绕任务关联。worker 可以检索过程，再按需读取细节；任务进展与模型用量可查看。源码与证据边界见[此前代码评估](saker-artex-gap-analysis-2026-10-08.md)。

ARTEX 确实有探索图、资产图、记忆能力，不能说它完全没有这些。但这些能力不能证明 Saker 的旧矩阵、自动记忆注入或独立管理器值得保留。本次查阅的 README 没有把 WebShell 管理作为独立主要页面列出；没有跑其产品，也不据此断言全仓库绝无相关实现。借鉴任务组织、按需读取、证据关联与复测路径，不复制页面数量，也不凭团队自述认定实际检出率胜出。

## 一个入口，三种研究方向

沿用聊天中的 Saker 渗透测试入口及常规、Nday、0Day 子模式。快捷栏只提供方向、协作方式、子代理上限及提示词/设置；任务状态放在任务与成果中。移除 AttackAtlas、战役记忆、WebShell 管理的运行包；移除 hunter 狩猎聊天页。资产平台配置与漏洞情报更新保留在设置中，Nday 后端继续提供匹配和维护能力。历史用户数据库保留，升级不删除数据。

三种方向共用原范围、任务身份、资料引用、请求回执、已用操作数、截止时间及子代理额度。方向只是研究重点；切换不能启动另一份任务预算。token 预算目前尚未具备完整全树强制预留，不将操作次数和界面统计称为 token 硬预算。

## Nday 的完整用户链路

1. 常规阶段取得范围内产品、版本、入口与身份条件，引用实际资料；产品不明时记录未知，不遍历所有 PoC 仓库。
2. 按相关产品检索固定版本知识，返回少量候选及来源/提交、受影响范围、前提和时效。模型辅助整理与排序；抓取、去重、增量和版本记录由程序完成。
3. 根据实际产品条件淘汰不适用候选。版本未知、功能未暴露或缺身份时分别记录待核实原因，不直接确认漏洞。
4. 有依据的候选进入当前任务的就绪工作。沿用已有正常请求和身份，避免主/子代理重复验证同一候选。
5. 保存原始回执、正常对照与效果证据，支持独立复核；只有适用条件和实际效果均成立，才成为已确认发现。
6. 找不到适用候选、环境受阻或预算耗尽时保存结果并结束/等待。常规→Nday 续接先释放旧 worker 再复用会话；共同推进分别保存两项状态，不能只完成一项就结束。

仅做 Nday、先常规后 Nday、共同推进三种安排必须覆盖以下验收：无产品线索、正确与错误版本、前提不满足、源记录过期、重复候选、身份过期、阴性相似响应、阶段确认、取消和重启、共用预算与 worker 回收。不能只测菜单切换或“阶段完成”字符串。

## 后续按同一验收合同推进

本批官方 Desktop 的 Nday 本地回合已验证 `tool_pack load nday` 与 `nday_policy_get`：初始 41 个工具的完整定义为 35,680 字节，Nday 加载后增加 14 个工具，变为 46,696 字节，即增加 11,016 字节。依据是原生请求头和上下文，不是新的 HTTP 传输抓包，也不是 token 节省对照。因此下一步优先拆分“当前任务的产品匹配/条件核对/验证”与“来源更新/整理/学习/维护”：任务中按需要取工具，维护在设置或后台工作中执行。旧 `nday` 包需要兼容迁移；不得拆掉来源维护能力或让 worker 冷恢复后缺工具。仅缩短工具定义还不够，须验证模型没有增加猜参数、重试、漏检或错误确认。

0.4.97 精简的 Desktop、真实模型工具清单、MCP 保留和桌面快捷方式验收已完成。随后[两组真实模型校准](verification/effect-interface-calibration-v2-2026-10-09/README.md)暴露了更具体的缺口：普通组 32 请求/166,715 token，Saker 组 19 请求/124,173 token，两者提交的两轮对照证据均不完整，独立确认均失败；普通组还超过了名义 150k token 额度。因此先修复证据完整性和逐请求预算准入，再完成常规/Nday 组合的冻结三组重复对照，不能先宣布成本降低。原生适配器已修复默认预设污染、晚注册子代理工具、耗时随查询增长及并发停止竞态，产品效果尚未得到证明。

后续贯通 Nday 就绪条件、证据版本、独立验证与复测，落实全任务树预算及并发故障对照。原 G0–G10 的性能、知识质量、发布可靠性与试用目标继续有效，但不再依赖被删除的图谱和自动记忆模块。

发布判据是用户能在官方 Desktop 完成设定→执行→查证→继续/停止→复测，阴性和环境失败不会被确认，Nday 衔接不重置额度，无遗留 worker；同时有相同模型条件下的效果与成本记录。未满足前只称学习或有人监督的有限试用。每次记录失败和未验收项，不能用新的版本号代替阶段出口。
