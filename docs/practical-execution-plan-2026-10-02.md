## 判断

目前不能证明 Saker 能省 token 或快速检出可利用漏洞。定稿时发现：`nday_match` 的 inventory 分支丢弃标题与技术栈；缺少 entryIds 时生成资产与目录探针的笛卡尔积，相同 URL 的不同判据重复发包，命中列表完整回灌上下文；attack_plan 包含通用产品词匹配和默认子代理分工。这些是最初问题记录，相关源码已有修复，实际收益仍须同条件对照证明。已有补证、复现、交付门禁需要接到生产执行链，而非再建一套平行概念。

最佳方向是：**先理解有限资产，再用单主代理调度有边界的工具批次，按观测更新下一步，只交付可复现影响。** 不能把“产品已知”误当作“所有组件已知”，也不能把一次 PoC 未命中当作资产安全。

## 执行流程

1. **一次建立资产画像。** 读取已有账本、有效请求、认证上下文、历史检查；缺什么才收集什么。每个服务保留协议、vhost、正常响应、技术与版本证据、登录/管理入口、JS/API、输入点、WAF/统一响应。共享 IP、相同标题不能合并应用或结论。
2. **画像缩小候选。** 精确产品/组件证据检索相关条目；通用词如 Java/OA/nginx 不能扩大为全库。缺版本保留未知；已知矛盾前提排除。未知产品先做有限识别，仍无证据则转实际输入面检查或留下缺口，禁止换批次反复扫全库。按资产的实际入口同时保留通用输入、权限、文件处理等路线，避免只有 CVE 路线。
3. **按批次执行。** 默认一个主代理，零自动子代理。确定性工具完成归一化、候选检索、请求去重、判据与负对照；模型只做路线选择、机制分析及异常解释。每批先计算真实请求、耗时上限和未覆盖项，再执行。一个完全相同的请求可供多个判据评估；不同身份、vhost、请求内容不得混用。无需默认为每个 CVE 搜一轮外网。
4. **失败必须分类。** 网络/WAF/登录/无效基线属于阻断，不能计作证伪。前提未知先补证；无区分度先重建对照；有效检查未命中只结束当前入口和方法。每个分支最多两次有新证据的补证，只有新增输入、身份、组件或方法修订才能重开。补证次数耗尽标“受阻/未覆盖”，随后调度另一条有依据的路线。不能无条件重试，也不能首个 PoC 失败就结束整个目标。
5. **方法按机制复用。** 公告、补丁、模板只读一次，形成版本化方法；共享前提与分析，不共享不同资产的命中结论。复测键包括资产、入口、身份、有效请求版本及方法版本。当前批内响应复用与跨轮缓存分别标明；跨轮状态过期或版本变化必须重测。
6. **交付看影响。** 指纹、缺头、版本、OOB 回调留在线索区。可复现权限边界突破、敏感对象访问或实际执行效果才进入有效发现。最低资料包括正常请求、变化请求、对照、观测、身份、时间、方法版本、复现步骤；身份边界类还需对象归属。模型自报 verified 或一段自评理由不能单独提升成果。

## 省 token 与查看结果

详细请求、响应和方法保存于工作区，模型默认接收有上限的增量摘要：新增资产/入口、最优候选、已执行数、复用数、阻断原因、下一步及证据引用。超过显示上限必须注明剩余数量和读取路径，完整台账不截断。不得同时回传完整对象和重复长篇说明。大内容按需查询，不把全库、完整工具输出或所有失败请求塞进每轮历史。

桌面工作台沿用现有任务/结果入口，默认突出“有效发现”，可展开“待验证”“受阻”“未覆盖”。每行能查看证据、前提、下一步、实际请求与成本；指纹命中不能显示成漏洞数量。停止时明确完成范围与缺口，有限预算耗尽不能显示“目标安全”。

## 实施顺序与验收

| 批次 | 生产改动 | 必须证明 |
|---|---|---|
| 1 | 同请求复用、总请求预算、完整台账与有限输出 | 实际本地 HTTP 服务计数下降；判据不丢；不同 Host/身份不合并；旧实现反向失败 |
| 2 | 资产画像接入 match/plan、无产品先补证、通用入口路线 | 已知产品不打无关探针；未知组件/版本仍留缺口；相关冷门条目不被热度截断；无全库隐式回退 |
| 3 | 统一生产任务状态、失败分类、有限补证、复测键、零默认派工 | 阻断不证伪；新证据能重开；同键不重复；另一条路线能继续；重启状态可恢复 |
| 4 | 影响验证与桌面证据浏览、增量工具摘要 | 统一响应/自评/回调无法交付；可复现影响可查看；原始证据可读；实际桌面无渲染错误 |
| 5 | 同模型同预算对照、发布与介绍重写 | 有效检出、漏检、误报、真实 token/请求/时间同时记录；真实 profile 同步，官方桌面实测 |

基准覆盖：已知产品混合目录、未知产品、隐藏组件、错误版本、软404、WAF、登录失效、同IP不同vhost、同请求多判据、首次方法失败后转路线、跨身份对象访问、重复发现、方法更新与断点恢复。测试场景必须有已知标签，包含确实可检出的正例与不能交付的负例。既检查真实发包也检查真实宿主模型回合，不能以 planner 的绿色单测替代检出能力。

机制验收要求零越界、零身份混用、零把阻断写成证伪、零把指纹直接交付。效率对照预先记录旧实现与新实现，使用同目标、模型、预算、认证条件与重复次数；报告首次有效发现耗时及中位数/最差值、有效发现数与漏检、误报、模型轮次、输入/输出/缓存 token、工具请求、外部查询、显示摘要字节。目标是在固定正例集合召回不下降且误报不增的条件下，降低请求与真实模型 token；未达到则调整，不宣称优化成功。请求数/字符数下降不能替代实际 token 数据；控制场景成绩不能替代真实目标实战结论。

每批修改必须同步官方桌面安装面并实际验证改动流程、加载状态与可见错误。需要登录时立即暂停桌面验证，通知用户，不代登录。暂未实现或未验证的批次不作完成声明。

安全/工具策略中断单列为受限覆盖：未执行与部分观察分开，不能计入完整阴性覆盖或验证通过。记录触发限制前已有成本及中断耗时，报告受限数量与覆盖缺口；不通过重复派发、改ID或改写请求绕过限制。优先以本地受控场景和正常业务对照验证执行机制，不能把这些成绩外推为真实目标检出能力。
