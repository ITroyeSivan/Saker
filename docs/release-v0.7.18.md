# Saker 0.7.18

本版完善“查已知漏洞”的负例路径：版本命中公告，但必要前提不成立时，明确记录为不适用，而不是当成漏洞。

### ✨ 新增功能

- “查已知漏洞”的逐目标验证步骤可以直接记录组件适用性。
- 公告区间支持 `[1.0.0,1.5.0)`、`>=1.0.0 <1.5.0`、`from/to` 等常见写法。
- 组件事实、公告和评估接受明确的同义字段，减少重复填写。
- 用户声明的产品或公告可以使用 `sourceRef="user-declared"` 记录，不必伪造一个不相关的回执来源。
- 公告的单个区间字符串和单个条件字符串会按一项处理。

### 🐛 问题修复

- 组件引用同时接受 `factId` / `componentId` / `componentFactId`，公告引用同时接受 `advisoryId` / `bulletinId`。
- 条件状态同时接受 `state` / `status` / `result`，证据引用接受 `evidenceRef` / `receiptId` / `evidence`。
- 无法解析的公告区间会明确报错，不再保存成空区间。
- 公告区间放在 `range` 字段或直接写成字符串时不再被静默丢弃。

### 🎨 体验优化

- 工具说明直接给出 observe / advisory / evaluate 的字段形状，减少试错调用。
- 负例结论仍显示版本区间命中、前提状态和回执引用，用户能看懂“为什么不适用”。

### ⚠️ 其他变更

- 版本命中、HTTP 200 或公告存在都不等于漏洞；前提不成立只说明本目标不适用。
- 不发布、不 push、不提交 Git。
