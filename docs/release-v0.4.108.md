### 🐛 问题修复

- 修正公开说明中子代理上限的表述：上限按宿主实际支持范围设置（官方 Desktop 默认 0–8，最高 16），与界面显示和拒绝逻辑一致。
- 复核与报告子任务现在按派发时登记的父任务轮次读取父任务的请求、检查、材料与发现，父轮次变化后拒绝旧子任务读取。
- 站点子代理、复核与报告共用按根任务的并发预留，上限 1 时并发请求不会绕过人数限制。
- 子代理工具面初始化失败会回滚并拒绝启动，不再只记录警告后继续执行。
- 知识条目只在真实发送成功后才标记“已发送”；连接前失败保持“发送未核实”，不提前计入已用。
- MCP 目标访问同时识别完整 URL、host/port/path 分离参数和原始 HTTP 报文，继续受未计量额度、范围和停止规则约束。
- 默认任务快照移除长操作教程和题面专用纪律，仅保留范围、预算、停止规则等必要事实；复测字段由工具 schema 提供。
- 执行记录现在包含正常模型消息、未形成消息的尝试、失败且无回执的 HTTP 工具调用，并保留真实终态。
- 效果评测冻结实际源码与安装文件的内容哈希，不再只散列来源字符串或包版本；复位状态只认独立复位凭据。
- 适配官方 Desktop 0.2.1 的当前工作目录：hunter、Nday、扫描器、Semgrep 与成果插件不再把相对路径落到最初项目目录，切换工作区后按当前目录解析。
- 自建接口遇到空响应、非 JSON 或 HTTP 错误时显示状态、类型和长度，不再只显示 `Unexpected end of JSON input`。
- 安装器新增 `--profile web`，升级时同步清理旧 Web profile 中已退役的方法编排、路由阶段和旧工具包，避免 Desktop 合并旧技能与旧工具定义。
- 移除渗透模式技能目录中残留的旧阶段门禁描述；旧方法编排与阶段门禁工具不再进入当前测试请求。
- 修复预设列表包装在插件停用后不恢复原函数的问题，热重载或停用后不再覆盖宿主或其他插件的预设注册。
- 诊断环境变量 `SAKER_CAPTURE_REQUEST_DIR` 可在私有目录捕获真实 `llm/stream` 请求，用于核对实际发送内容；默认关闭。
- 修复官方 Desktop 0.2.1-rc.2 下焦点不在面板内时 Esc 无法关闭「提示词模板」和「测试设置」的问题。
- 导入的测试资料在列表与详情中显示用户填写的可读名称，不再出现 `pasted-<uuid>.txt` 这类内部文件名。
- 发现缺少复现方法时，详情显示“还没有完整复现方法：请先记录入口、成功标准、复核步骤与恢复方式”；内容不是有效 JSON 时提示重新保存，不再显示英文解析异常。
- 公开资料与来源说明里指向开发机路径、内部脚本的写法已改正，不再给出用户本机不存在、照抄就会失败的命令。
- 知识检索没有命中时，结果里明确给出没有命中的那条查询，不再只返回一个空列表。
- 界面字号统一回设计令牌（辅助 12px、正文 13–14px、分区标题 16px），原先散落的 10 / 11 / 11.5 / 12.5 / 15px 全部归并，设置页文字大小不再参差。
- 测试资料的变化通知与搜索结果标明上限按 UTF-8 字节近似计算（当前没有可靠的 token 计量器），不会把字节数当成精确 token。
- 提示词模板的插入落点改为打开抽屉前记录：输入框里选中文字时按钮显示“替换选中文字”；抽屉打开期间输入框被改动时改为换行追加到末尾并如实说明，不再直接拒绝。
- 界面样式表里的字号也统一回设计令牌（此前只收敛了内联样式，CSS 里仍散着 9.5 / 10 / 10.5 / 11 / 11.5 / 12.5 / 15 / 17 / 18px 共 90 余处）。
- MCP 工作台的命令改用 12px/18px（原为 `font:` 简写里的 11px），命令被省略号截断时悬停可看到完整内容；字号门禁也补上了这种简写写法。
- 同时工作的助手默认值改为「自动，最多 2 个」（此前默认落在「最多 1 个」）。
- 「设为新会话默认」改名为「存为默认偏好」，提示补全为它实际保存的项（询问、汇报、解释原理、助手和测试内容），并说明目标、账号、排除路径与已用量不会复制到新任务。
- 固定能力说明标明上限口径（没有 token 计量器时按 1800 UTF-8 字节近似控制）并加门禁，防止以后往这段提示里加句子而没人发现。
- 筛选测试内容后，模型会收到一行已选重点（默认全选不发送完整清单），默认不检查的 CORS 与开放重定向也单独一行。
- 修复官方 Desktop 0.2.1 下 `redteam_context` 工具 schema 被宿主编译器拒绝，导致 Saker 接口加载失败、资料导入抛出 `Unexpected end of JSON input` 的问题。
- 复测不再按“超过 15 分钟”一刀切作废：回执是否仍有效改看当前请求、身份、目标实例和内容完整性；没有相关变化的正常对照可以继续使用，需要重验时指出具体失效条件。
- “本次未复现”现在必须同时引用同一次复测的正常功能对照回执（同源、同身份、2xx），单独一张目标回执不能证明修复；403/404 只有在正常功能对照仍可用时才支持未复现，登录失效、限流和服务端错误只能记“无法确认”。
- 标记“已修复”与复测留档改为同一次事务提交：任一步失败都不会留下字段已改、复测未写的半更新；同一次调用同时给 `fixed` 与本次复测结论时，依据本次新结论判断，不沿用旧记录。
- 复测留档时间由服务器决定，请求体不能把时间改到过去来伪造“最新”顺序。
- 发现列表的验证提示改为“上次验证与当前请求、身份或目标实例不匹配，需要重新验证”，不再显示已经废弃的 15 分钟过期说法。
