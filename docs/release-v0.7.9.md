# Saker 0.7.9

本版把方法执行从提示文字改成可验证的完成合同，修复停止后复活和图语义静默降级，并收紧扫描能力探测。

### ✨ 新增功能

- 方法步骤新增完成依据类型：“结构化材料”或“真实执行回执”。
- 方法编辑器、阶段图和步骤预览会直接显示当前步骤需要哪类依据。
- 执行回执会绑定工作流运行、步骤、目标、身份和采集时间，并防止同一回执重复用于多个步骤。

### 🐛 问题修复

- 分析步骤必须提交结构化材料；真实执行步骤必须引用当前会话中仍有效、目标匹配的宿主回执。
- 空说明、任意字符串、其他会话或其他目标的回执、失败或过期回执都不能推进步骤或把方法标成完成。
- 同一份回执不能静默满足两个步骤；完成绑定会记录运行、步骤、目标和身份。
- 停止改为终态。停止后的迟到推进、旧修订回调会被拒绝，不会把运行恢复成 `running`。
- 保存或导入只支持线性步骤时，显式跳转、边、分支、循环等控制字段会明确拒绝，不再静默改写为顺序执行。
- 仅有 `pwsh` 不再被当成 `semgrep_scan` 已就绪；只有通过二进制、版本和输出合同验证的 Shell 适配器才显示可用。

### ✅ 结果表达

- 方法结束和“目标验证成功”分开表达；全部有序步骤完成时给出方法账本状态，未知或受阻会保留为 `inconclusive` / `blocked`。
- 浏览器回执增加内容哈希并在读取时复验；执行回执继续使用现有完整性、目标和请求修订校验。

### 🎨 体验优化

- 方法编辑器新增“推进时必须有什么”，可在“结构化材料”和“真实执行回执”之间选择。
- 阶段图和方法预览直接显示“需材料”或“需真实回执”，避免执行完才发现缺依据。

### ⚠️ 其他变更

- 当前仍只支持 2–12 步线性方法；自由分支、循环和任意拖拽重接未实现，并会在保存入口明确拒绝。
- 需要 Node.js 24.9 或更高版本；当前适配官方 Desktop 0.2.2-rc.1。
- 本版不发布、不 push、不提交 Git。
