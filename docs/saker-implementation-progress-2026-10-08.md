# 下一阶段实施进度

目标仍是 [G0–G10 完整验收合同](saker-next-stage-goals-2026-10-08.md)：提高真实任务效果和效率。以下是实现进度，不是效果基准成绩，也不代表全部目标完成。

## 第一批：依赖任务内核（0.4.93）

复用现有 `operation-state.json`、锁、状态机和项目工作台，加入前置任务、产物哈希条件、稳定任务键、执行租约和就绪查询。前置条件未满足时，领取和启动会拒绝；工具包装器遇到依赖拒绝后不会继续执行实际请求。原生工具守卫也检查匹配任务的前置条件。

任务工作流在渗透模式下按需加载，避免小问题每轮携带七个工具声明。本地账本操作不要求先创建目标扫描预算；目标请求继续受原有预算守卫约束。

官方 Desktop 验收发现并修复了工具过滤、嵌套参数 schema 导致插件激活失败、工作台空响应、账本被误判为目标操作四个接入问题。失败轮次保留在 [实际验收记录](verification/task-dependencies-2026-10-08/README.md)。当前只是 G2 的第一部分；尚未实现事件合并调度、取消传播或全树预算预留。

## 接下来怎样判断是否保留改进

先补 G0 与 G1 的能力和效果基线，定稿 G3/G5 共用契约，再接持续调度、独立验证和同站双角色。当前内核先修复了实际使用阻断；不能因此跳过效果对照。新增结构只有在提升独立成功、减少错误确认，或保持效果同时降低请求/模型用量/人工介入时，才扩大默认使用范围。

没有启动周期自动化；没有完成 ARTEX 与 Saker 同条件运行比较。第三方代码只作为设计研究，未复制 AGPL 实现。

## 2026-10-09：消除实际任务启动浪费（0.4.94）

任务工具开始参数改为独立字段及枚举，旧JSON兼容；进度说明与独立完成标记正确合并。第一轮官方Desktop首次start成功，8个对照请求被独立评分证实，界面完成状态持久化。后续复测暴露成果登记逐项猜字段，11次失败将整轮拉到20步、687K token，因此同批修复完整格式契约与恢复指导。恢复轮实际第三次登记成功，8个请求独立评分通过，12步、317K token；成果仍待独立复核。没有随机对照，不能声称稳定节省。工具说明保持原有预算；证据校验不放宽。[验收记录](verification/task-inputs-2026-10-09/README.md)保留全部失败、用量和验证边界，G0–G10整体未完成。

新增[本地靶场、独立评分器和协议](../benchmarks/task-effects/README.md)。36 个案例和 8 组行为检查通过；官方 Desktop 的一个有明确步骤指引的阳性接入冒烟也被独立评分证实，实际 8 个请求、0 错误确认。它不是三组效果评测，G1 仍未完成。
