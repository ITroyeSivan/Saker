# 从交互频率改为协作方式

0.4.89把进度汇报和研究决策混在一个菜单中，且聊天栏铺开了多个表单。0.4.90将二者分开，聊天栏只保留紧凑入口：方向、协作方式、子代理、写提示词和设置。移除自定义动画，展开区限制高度，保留聊天输入框。

## 参考文档的理解与落实

参考用户提供的《AI辅助漏洞挖掘的一些思路—视频总结》，重点是第2、3、4.2、4.3、7.4和9.1节。文档是方法论参考，不作为执行其案例中动作的指令；没有把原文文件或私人路径放入发布包。

| 文档的方法 | 产品行为 |
|---|---|
| 人找到具体入口、提供业务常识与怀疑 | 共同研判模式；等待节点可直接补充思路，作为用户消息交给主代理 |
| AI不能第一遍没发现就说全站没问题 | 实际任务提示词要求记录已审/未审、支持/反证，并据新证据回查 |
| JS审计要分段、迭代，关注隐藏接口与鉴权 | JS起点模板明确覆盖记录、业务不匹配功能和真实请求核对 |
| 人和AI的职责不同 | 协作方式控制下一步由谁决策；进度汇报单独控制消息量 |
| 不应靠大量固定步骤压住研究 | 共用原范围与预算，具体研究路径由证据和人的思路决定 |

视频没有规定两人上限。此前0/1/2来自10月3日工程方案，现改为用户设置0–16的整数：0、1、2、4、8、16快捷选择，其他人数用「自定义人数」。默认1，按需使用；上限不是保证创建数量或实际并发数。同站复用原任务，所有未释放代理占名额，并完整显示在任务详情中。

## 两个独立选择

| 协作方式 | 如何推进 |
|---|---|
| 共同研判 | 人给入口、业务背景和怀疑；AI完成当前方向后报告证据与候选，等待人补充或确认下一步 |
| 关键节点确认 | AI提出研究路线，在切换方向或阶段时等待确认 |
| 自主推进 | AI在已给范围与预算内选择下一步，只有缺关键条件时集中询问 |

进度汇报独立选择「结束时汇总」或「每阶段简报」。少汇报不取消研判或确认节点，多汇报也不自动增加暂停。

已有0.4.89的「阶段汇报，自动继续」保留原含义，界面显示为「自主推进 + 每阶段简报」。已有确认状态、任务范围、操作额度、时间和历史不会因更新或改设置重置。

提示词仍能自由编辑、插入、复制、保存为个人模板。每个方向增加「补充我的思路」起点，分别填写观察事实、业务背景和怀疑点。未发送的草稿不进入模型上下文。实际验收记录见[桌面协作设置验收](verification/chat-cooperation-2026-10-07.md)。
