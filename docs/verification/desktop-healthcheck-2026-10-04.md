# 桌面快捷方式与功能复测（2026-10-04）

本轮已恢复桌面的 MCP 和工具配置，修复 MCP 接入、列表刷新及执行记录问题，并通过官方 dsh Desktop 实测。桌面现有 **Saker (dsh Desktop)** 快捷方式，以后直接双击启动。

版本：官方 Desktop 0.2.0-rc.2；Saker 0.4.86；MCP 工作台 1.2.2。本报告补充本次检查，不替代前一轮框架和成本对照报告。

## 快捷方式与记忆

“每次更新后创建或刷新桌面快捷方式”已写入工作区 AGENTS.md。安装脚本会刷新实际 Windows 桌面的快捷方式；稳定启动脚本位于 `_ref/tools/Start-SakerDesktop.ps1`，应用位置保存在相邻 JSON 中。更新应用目录时继续保留原来的用户数据目录及 `.dsh` 配置。清理脚本也已将这两个文件列为长期保留项。

实际通过 `.lnk` 启动了官方桌面，未开启调试端口。原会话和 Saker 入口可见，MCP 设置仍保留 Burp、Yakit；插件页显示 25 个已安装插件，包含 MCP 工作台。该启动脚本是本工作区的便利入口，不是官方规定的安装方式。

## 查出的真实问题与处理

| 问题 | 处理及证据 |
|---|---|
| 桌面 MCP 列表为空 | 原 Web 配置仍有 Burp、Yakit，桌面未带入。通过桌面设置接口恢复两项，后续安装与快捷方式重启均保留。 |
| 桌面工具库为空 | 恢复原来的 16 条工具、1 个根目录、2 个服务及相关设置。保留桌面正在使用的模型配置。 |
| 无害 MCP 代理接入可用，直接接入报配置校验错误 | 将宿主反射的环境变量、请求头字典转成普通对象后传给官方 MCP 客户端。实际直连与代理均返回正确 ping 回执。 |
| 状态计数变化，服务器卡片却不刷新 | 增加已保存配置的定时读取；有未保存修改时停止主动刷新。实测移除两项临时服务器后，卡片自动由 4 项变为 Burp、Yakit 两项。 |
| 同步挂载错误被状态清理覆盖 | 保留仍在配置中的启用服务器错误状态；反向测试可以检出旧实现。 |
| 被拒绝的调用被记为成功，代理调用漏记 | 读取桌面结果的 `message.isError`，记录 `mcp_call`，并解析实际桌面的 JSON 字符串参数。最终桌面日志准确显示两项服务、工具名与成功状态。 |

更新前后桌面配置文件 SHA-256 一致，安装没有覆盖配置。最终安装由官方桌面 CLI 完成，并核对了包内安装字节。现有设置、接口和模型回合都在官方桌面运行。

- 10 个读取接口：安全配置、MCP 状态、方法列表、技能列表、知识统计、知识包状态、连接列表、记忆统计、分类目录、小任务状态。全部 HTTP 200，返回成功。
- 知识库：23/23 个知识包已安装、失败 0；索引 12,763 文档、158,031 分块，状态 ready。首次页面短暂显示未加载计数不能视为知识丢失。
- MCP 测试 71 项通过、失败 0。六项反向验证分别撤回修复，均出现断言失败，随后恢复源文件。

最终模型使用 **Low**，任务预先设为 8 次操作、3 分钟、0 子代理。实际仅调用直连 ping、代理 ping，以及一次任务完成操作：

| 路径 | 实际回执 |
|---|---|
| `mcp__saker_health_direct__health_ping` | `HEALTH_OK:direct-verified` |
| `mcp_call` → `saker_health_proxy/health_ping` | `HEALTH_OK:proxy-verified` |

模型回合已结束，小任务为 `plan_complete`，没有派发子代理。首轮直接发起 ping 时缺少小任务配置，被本地守卫拒绝并产生了额外配置调用；最终轮从桌面任务入口提前设置后正常完成。不能把首轮算成“两次调用即成功”。
