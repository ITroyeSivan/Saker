# 评测资格与超预算结果：官方 Desktop 验收

2026-10-09。产品保持 0.4.98；本次仅修改独立开发适配器 `@saker-dev/effect-benchmark` 0.0.6、评分汇总和测试。它不进入生产预设、安装包或发布包，验收后通过官方 CLI 卸载。

## 改变的行为

之前 `summarizeRuns` 直接累计评分器的 `independentSuccess`，没有排除超额、不可比或未结束运行。现在原始评分保持不变，额外核对请求、token、时间、可比性、结束/清理状态、工具隔离和人工介入记录。

汇总的 `independentSuccess` 表示合格成功；`rawIndependentSuccess` 单独保留原始独立评分成功。预算未知、超额、条件不可比、隔离失败等逐项列出排除原因。错误确认和消耗在被排除的运行中也继续计数，缺失计数保持 `null`。重新核对实际字段，不信任旧存档中的资格结论。等于额度允许，超过额度排除。

使用宿主的非重叠输入、缓存读/写、输出计数。非整数、溢出或与提供方总量矛盾的用量保持未知。这里核对的是结算后的实际消耗，不是调用前硬预算。

## 实际 Desktop 结果

- 官方 Desktop 0.2.0-rc.2，日常 home、用户数据及 Saker 0.4.98。
- 私有适配器真实激活，控制端 `inventory/start/status` 路径工作；已安装的三个改动模块与源码 SHA256 一致。
- 原生 standard 单代理临时副本，只有 `exercise_request`、`exercise_submit` 两个工具；未改原预设。
- 本次故意设置 1 分钟、2 个目标请求、100 token 总额度，以暴露一次请求就可能越额的问题。不是已校准的效果实验。
- 原生会话生成 1 次，实际 5,641 token，耗时 3,815 ms，目标请求 0。输出达到 100 token 上限后截断，无最终提交；独立成功为 false。
- 控制端资格为 `eligible=false`、`qualifiedSuccess=false`、`budgetStatus=exceeded`；原因包含 `tokens-budget-exceeded` 和 `runtime-not-comparable`。任务结束并完成清理，无工具隔离错误。
- 打开该会话查看截断提示和用量；没有 slot 渲染错误。设置页实际显示 MCP 2 启用、2 连接、176 个目录工具；保存禁用，配置未编辑。未执行 Burp/Yakit 具体工具，连接不能代替工具冒烟。

这次实际模型运行没有成功发现漏洞，不能用它证明“超预算的成功被排除”的模型效果；该行为由针对性测试与反向测试证明。原生运行证明的是预算超额事实及真实控制端资格计算。会话生成计数不包含后台标题等辅助调用，不代表全任务树总成本。

对旧两组校准重新核对：普通组 166,715 token 超过 150k，被标为超额；Saker 组 124,173 token 在额度内。两组原始独立成功均为 false，且都不具备正式比较资格；旧失败没有改写或删除。

## 尚未完成及下一步

调用前 token 准入、原子预留/结算、子代理和辅助调用共享额度仍未完成。本次 100→5,641 的记录正是反证，不把输出上限或事后排除称为硬预算。
