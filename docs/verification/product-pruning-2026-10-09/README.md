# 旧模块移除、Nday 保留与实施状态验收

2026-10-09，Saker 0.4.97；Windows 官方 dsh Desktop 0.2.0-rc.2。日常 `.dsh` 与 Desktop 用户数据继续使用；实际应用的渲染器调试接口操作，不是另起 Web 或模拟宿主。没有目标测试、知识更新、子代理或登录操作。

## 真正移除了什么

统一生产清单排除 AttackAtlas、campaign-memory、WebShell 管理，打包/两个安装入口/桌面交付使用同一选择。官方 Desktop 安装命令实际移除三个已安装包，当前交付为 22 项。源目录保留历史研究与兼容测试，用户历史数据库不删除。hunter 聊天页不再注册，但资产平台与漏洞情报设置及 Nday 后端继续工作。

移除成果自动上图、链路反查、图谱对账工具、默认图谱句柄，以及发布提示词中的图谱/跨任务记忆要求。路由使用独立本地关键词；新工作方向只允许 boot/criterion/scope/finding，宿主默认解析器拒绝无法核实的旧 chain 节点。

Desktop 实际页签为“对话、轨迹、任务与成果、项目工作台”；旧三项及 hunter 页消失，inventory 不含三个退休包和临时基准插件。hunter、nday-hunter、成果、路由、阶段账本和 MCP 均 active。当前自建验收会话无可见错误。

## Nday 验收的实际范围

实际点击聊天栏，常规/Nday/0Day 三种方向均保存；单一方向、常规→Nday、共同推进三种安排均保存，0 子代理选择保留，未启动任务。[界面记录](native-flow.json)不能代替真实漏洞效果或本版完整阶段执行验收；此前阶段续接与预算证据见[历史进展](../../saker-overview-and-progress-2026-10-07.md)。

两个本地模型回合：先 `tool_pack load nday` → `nday_policy_get`，读取实际本地策略；更新后再 `tool_pack load task-workflow`，检查实际请求中工作方向 schema 的四种锚点，不含 chain。三次工具调用均返回有效本地结果，回合结束。没有调用目标工具。

[原生请求头/上下文与实际调用](model-tools.json)中，默认 41 个工具定义为 35,680 字节；加载 Nday 后 55 个、46,696 字节，增量 11,016 字节；更新后加载任务工具为 48 个、42,362 字节。无退休工具名或旧提示词标记。此为原生模型装配证据，没有本批新的 HTTP 传输抓包；不能据此宣称同比 token 节省。Nday 全包仍含 14 项工具，任务匹配与来源维护分开按需加载是后续优化项。

两回合主会话记录共五次模型生成，累计 99,318 token，其中缓存读取 86,272、非缓存输入 12,557、输出 489；宿主另有标题生成事件，本记录没有完整计入其用量。缓存仍有成本，不将缓存读取当成零计费，也不将工具字节等同于 token。没有 ARTEX/普通 Agent 同条件对跑。

实际打开“漏洞情报更新”，页面正常显示，没有空 JSON 错误；实际打开 MCP 工作台与原生 status 一致：Burp、Yakit 两项启用、0 连接、0 工具。[设置记录](native-settings.json)。只能称配置仍在，不能称离线服务业务可用。
