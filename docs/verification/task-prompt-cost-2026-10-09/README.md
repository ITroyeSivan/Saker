# 聊天读取与动态任务上下文验收

Saker 0.4.95、dsh-redteam-results 1.0.45；Windows 官方 Desktop 0.2.0-rc.2，日常 home 与 userData 不变。先实际启动 Windows Desktop 的稳定快捷方式，再通过所属官方应用的调试接口操作聊天、人数、任务开始、停止和 MCP 设置。未要求登录，三个相关插件 active，界面无可见错误。

## 修复及反向检查

聊天加载和轮询不再自动 task.choose。显示的默认方向不构成持久选择；实际加载、轮询之后 choice/options 均 null，用户明确把人数改为 4 后才持久化 regular/single/continuous/workers=4，尚未开始任务。保留原有明确控制、新会话默认和运行任务约束。

任务动态文本从 system section 移到 context；稳定系统约束要求以最新宿主持久快照为准。已完成任务的真实工具守卫仍拒绝操作。会话隔离、非渗透预设无注入、旧宿主兼容路径均被执行检查。三个隔离机制回退（动态整份系统文本、丢失 context、读取时自动写入）分别触发对应行为失败，生产文件哈希未变。

完整回归见 [日志](regression.log)：91 套、13,634 通过、0 失败、16 跳过，87 个必需套件齐全。包含 25 组实际聊天组件行为、3 组实际工具/上下文行为、4 组反向输出，以及官方编译器对 20 个实际工具 schema 的检查。

## 原生请求体与语义验收

只在当前验收会话的所属 backend 中观察原生 fetch 字符串 body，原参数原样转发；不读取或写出鉴权头。记录 8 个 body，原始长度与 SHA256 和字节分项核对，退出前恢复原 fetch。原始 body 含工作区指令，只在临时目录保留，不公开；[哈希与观察记录](transport-capture.json)、[字节审计](byte-audit.json)不含原始提示词。

7 个主请求的 system 和 tools 逐字相同，工具 41 个、35,762 字节；版本清单仍 13,286 字节，其是否计入模型 token/费用未知。第二轮相对[上一版原生实验](../model-request-cost-2026-10-09/README.md)从 95,415 降到 84,620 字节，减少 10,795 字节；明确编辑后的第三轮比旧实验第三轮少 6,570 字节。提示词长度、模型回复与缓存不同，不能作为严格同条件 token 或费用效果比较。

模型正确报告方向 regular、人数 4；实际任务开始保持 0/3，停止持久化 cancelled 且 0/3。随后模型答复“任务已 cancelled、目标操作全部停止”，界面显示“本轮已停止。保留资料，设置下一轮”。[实际桌面状态](desktop-state.json)保留观察。取消前，模型将缺少站点描述为“待资料”，但实际 stopped=false；模型文字不作为状态权威，没有把该措辞计为正确停止状态。

[实际 provider 用量](provider-usage.json)累计 7 次主响应、147,243 token：非缓存输入 24,092，输出 1,551，缓存读取 121,600。前三轮合计 53,848；辅助标题用量及金额未知。没有调用目标工具、产生目标 HTTP 流量、登记漏洞或完成独立交付；该实验只证明接入、状态和传输成本机制。

## 限制及后续

变化时仍追加整个聚合 runtime context，约 4.7–5.0 KB。打开成果标签页也改变该聚合上下文；不能声称历史已不增长。模型报告还指出既有 route-boost phase=mobile 与任务 regular 并存，属于待解决的提示信息一致性问题。本轮没有改变用户的已有配置去隐藏该现象。

MCP 设置实际为 2 个配置、2 个启用、0 个连接、0 个工具，Burp/Yakit 均 unreachable；已安装不能证明可用。原始 body、调试脚本和本轮所属临时文件收工回收；官方 Desktop 产生的合成验收会话保留在日常用户数据，不删除用户会话。G0–G10 保持未完成，优先继续真实能力体检、模型适配与冻结对照、运行上下文重复内容归因。
