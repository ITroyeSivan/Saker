# Saker：由人选问题，AI集中验证

当前版本 0.4.86，面向官方 DeepSeek Harness Desktop 0.2.0-rc.2。逐项桌面验收和成本对照见[验证报告](verification/framework-desktop-2026-10-03.md)。

Saker帮助你研究一个具体站点问题。你提供目标、业务信息、账号或已有请求；AI查相关资料、追调用、比较正常与异常行为，保存可复现证据。资料不足时先做有限观察，给出几个具体方向供你选择。

## 三个子模式

只保留“渗透测试”一个专业入口，下面有三个重点。历史代码审计和CTF会话仍可读取，不再列为新任务入口。

| 子模式 | 你给什么 | AI围绕什么推进 |
|---|---|---|
| 常规测试 | 一个站、账号或流量、重点功能 | 这个功能的角色、对象、输入和业务流程是否正常 |
| Nday发现 | 少量资产及产品、版本或已有扫描线索 | 少量相关公开漏洞是否满足条件，方法是否真实有效 |
| 0Day挖掘 | 一个疑点、页面、请求或相关代码 | 这个业务异常的原因、权限边界和实际效果 |

三者共用已有资料。登录页面、前端JS和普通功能都能作为研究入口；请求验证再核对实际身份和正常对照。不默认从一个URL扩展到全机构，也不拿整库模板逐个尝试。

这一轮结束后，在成果页点“保留资料，选择下一轮问题”。你重新选择问题、重点和预算，资产、请求、材料和证据继续保留。当前任务仍运行、访问受阻或子代理未释放时，不能用新一轮绕过限制。

## 一轮怎么做

例如你问：“地图站的普通账号为什么能调用人员档案接口？”AI先追相关调用，核对凭证来源和用途，再比较受控对象的实际权限。接口名称、无凭证401、带凭证200、前端菜单变化都不能直接当漏洞。上传接口还要追到对应业务、文件用途、服务端效果和恢复状态。

相关线索在当前问题内连续推进，无关线索留待办。不会发现一个疑点就等你回复；只有缺关键资料、有效路径走不通、需要改变任务或本轮完成才集中讨论。一个方法未命中不等于整个站安全。

小任务由主代理直接处理。只有确实需要隔离较多站点材料或分担清楚的深入任务才创建子代理，通常一个，最多两个。同站复用，子代理不能再派代理。完成、失败、取消、超时或等待资料时保存短报告并关闭；关闭失败仍占名额，界面显示实际状态。

IP明确被封、登录失效或正常访问受阻时停止受影响请求并报告，不反复绕行。恢复由你处理，随后先复查已存正常请求，再继续原问题。实际策略中断保留“受限／未覆盖”，不能写成阴性或成功。

## 怎样减少重复工作

- 方法组合每轮提供短目录，相关正文按需读取；不把全部方法正文常驻注入。
- 选定JS文件按内容缓存，返回新增线索和位置；第二遍按具体疑点读相关函数、认证包装、加解密、chunk和必要源码映射。动态调用、缺文件和解析失败明确保留为未覆盖。
- 已存正常／异常请求可在一个批次调用中执行，程序记录预算、真实报文和事实差异。模型只解释差异，不重复填写已知事实。
- 支持疑点的读取对照可以直接引用其ID登记待复核线索；程序填入已有报文和方法，不让模型重复抄写长JSON。未解释或支持疑点的结果不能写成“未命中”。
- 原文、报文和过程保存在本地，聊天读取摘要和必要片段。主代理不重新分析子代理看过的全部材料。

五组真实桌面模型回合采用相同题目、夹具、预算、DeepSeek-V41-Flash和Max推理设置，合计主代理及全部子代理：

| 任务 | 修改前token | 修改后token | 变化 |
|---|---:|---:|---:|
| 常规对象权限比较 | 460355 | 188134 | 减少59.13% |
| Nday适用条件核对 | 108968 | 134645 | 增加23.56% |
| 0Day业务调用与权限 | 484369 | 395020 | 减少18.45% |
| 一个子代理 | 397251 | 255441 | 减少35.70% |
| 两个子代理 | 318948 | 224318 | 减少29.67% |

**Nday这组没有变高效。** 按需加载多一次模型回合也有成本，模型回答长度和缓存状态会影响结果。每组只跑一次，修改前后还包含接口易用性修复，不能把改善全部归因于工具精简，更不能承诺真实站点稳定检出。常规测试旧版漏掉了线索登记；0Day旧版未读到选定JS，新版补齐了这些环节，均属于交付或材料覆盖改善。两版都没有把菜单和公开地图key误报成漏洞。

任务面板分别显示目标操作预算和模型统计。后者包含资料阅读、工具调用、主代理及全部子代理的token、缓存和模型运行时间；并发用时合并，缺少的统计明确标为未知。不估算金额，也不把缓存命中当作免费。

## 怎样确认结果

执行回执证明请求实际运行，响应差异只是待解释事实。私有JSON读取可用已审阅的业务条件自动对照；文件读取、业务状态变化等其他效果可以在桌面成果详情中独立人工复核，明确权限预期、实际效果、证据及恢复情况。两类复核分别标明来源，不互相冒充。

没有对应执行或证据失效的记录不能进入可交付列表。HTTP回连不是RCE，人工勾选也不能把普通HTTP结果变成执行证明。未验证的线索、未命中与受阻保留在过程区。

## 更新公开漏洞资料

1. 打开“设置 → 漏洞情报更新”。
2. 勾选来源，点“更新已选源”；选择自动保存，无需先理解复杂策略。
3. 单个来源失败时点“更新此源”重试。后台运行，可以离开页面。
4. 看每源进度和实际失败原因。“部分完成”表示达到本轮上限，可续传，不表示全库已覆盖。

CVE、NVD、OSV、GHSA、CISA KEV和公开研究仓库各有覆盖与上游限制。公告入库不等于方法可执行，PoC正文需核对适用条件和审阅。SRC范围策略入口已移除；目标范围和实际授权仍需明确。

## 安装、工具和插件

在官方桌面端配置可用模型。仓库运行`node scripts/pack-all.mjs`生成根包和24个插件包，完全退出应用后用`scripts/install-desktop.mjs`或官方插件管理安装。不要把源码改动当成已打开实例已更新。

浏览器与Burp/Yakit MCP适合走业务和分析数据包；扫描器仅按具体方法需要加载。没有安装的工具不能假装已运行。无需为每个小任务准备完整扫描工具链。

| 工作 | 主要插件 |
|---|---|
| 模型、工具路径与MCP | sec-config、mcp-studio |
| 资产与公开漏洞资料 | hunter、nday-hunter、knowledge-hub |
| 按需扫描与相关源码检查 | scanner-tools、semgrep-audit |
| 模式与测试方法 | mode-group、method-stack、skill-browse |
| 工具可见性与执行约束 | tool-scope、sec-enforce |
| 任务、证据、复核和交付 | redteam-results；其他旧台账功能按需使用 |
| 历史记忆和可选执行后端 | campaign-memory、product-subagents |

全部插件职责和兼容说明见[插件清单](plugin-list.md)。Saker站点子任务使用宿主原生生命周期；外部CLI不替代其数量、层数和释放保证。auto-advance默认关闭；旧CTF插件保留兼容，不作为当前任务入口。

完整操作见[首次配置](getting-started.md)，本次验收与剩余缺口见[实施台账](nday-implementation-audit.md)。桌面要求登录时立即暂停验证，由你本人登录。
