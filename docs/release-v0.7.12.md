# Saker 0.7.12

本版修复真实业务走查中暴露的工作推进、请求凭据和执行记录衔接问题。

### ✨ 新增功能

- 工作流工具现在返回稳定的步骤 ID、运行 revision、当前允许动作和下一步，无需模型猜 `1`、`step-1` 或省略参数。
- 附件中的原始 `.http` 请求可通过 `redteam_context importRequest=<materialId>` 导入，生成可执行 requestRef 和会话内 credentialRef。
- Authorization、Cookie 和常见认证头由宿主保存并在派发时回填；模型只能看到遮蔽后的材料和不含秘密的回执。
- 同一条公开请求可由两个不同凭据各自导入；requestRef 与 credentialRef 按身份分离，不再互相覆盖。
- `redteam_execution action=run` 可从已导入请求派生查询参数，Host 保留 credentialRef，模型只指定变化的参数。

### 🐛 问题修复

- 省略 stepId 时使用实际当前步骤；错误或迟到 stepId 返回当前可推进步骤，而不是只报 `workflow step not found`。
- 原始请求导入按完整 URL、Host、方法、请求头和正文建立引用；请求凭据与应用账号标签分开记录，不再把带认证头的请求当成 anonymous。
- 工具调用完成但业务拒绝时，执行记录按失败显示；不再把错误 ID、身份拒绝或工作流错误算作完成。
- 会话栏把结构化 HTTP 回执标为“回执”，避免把 shell/CLI 未计量请求暗示成完整总数。
- 材料分段读取同样遮蔽认证头，关闭绕过请求导入读取原始 token 的旁路。
- 自由测试场景保留请求导入、成果登记和成果修订入口；不再把真实任务闭环所需的工具误当成低频管理项隐藏。

### 🎨 体验优化

- 模型被明确要求在候选结论出现时调用成果登记，不再只写 Markdown 报告。
- 仍然只有一个紧凑会话栏；完整范围、账号、回执和用量继续按需进入任务详情。

### ⚠️ 其他变更

- 当前仍只支持 2–12 步线性方法；对比实验继续暂停。
- 本版不发布、不 push、不提交 Git。
